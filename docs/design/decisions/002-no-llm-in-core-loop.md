# 002 - 核心主循环禁止使用大语言模型（LLM）

- **状态**：已采纳 (Accepted)
- **日期**：2026-11-14
- **决策者**：架构组

## 1. 背景与上下文 (Context)
Vale Chronicle 需要处理人物的决策（种田、借粮、偷窃）和多轮交互（讨价还价、争吵）。目前业界的常见做法是使用大语言模型（如 GPT-4）来驱动 NPC 对话和行为。

## 2. 决策 (Decision)
在模拟器的主循环（Tick Engine）和核心逻辑（Agents 的决策、Interaction 的谈判）中，**绝对禁止**同步调用任何大语言模型 API。必须使用确定性的规则引擎（效用函数、门槛判定、状态机）。

## 3. 后果与影响 (Consequences)

### 优势：
- **极低成本与高并发**：跑 10 万个 Tick，上万个 NPC 参与决策，纯 Python 计算只需几秒钟，不产生任何 API 费用。
- **确定性与可重放**：配合事件溯源，同样的配置、同样的随机种子，跑出的结果绝对一致。LLM 的随机性会彻底破坏因果链。
- **世界观稳定**：规则引擎绝不“幻觉”，不会出现中世纪的农民突然使用互联网的荒谬情况。
- **快速快进**：不依赖网络延迟，随时可以“快进”几年查看演化结果。

### 代价与限制：
- 必须花大量精力设计 `04-needs-and-utility.md`（效用函数）和 `interaction/02-negotiation-dynamics.md`（拉扯状态机）。
- 文本不够生动（第一版输出可能是“林远对李全发起了 steal_asset 动作”）。

## 4. 补充（未来的旁路接口）
LLM 可以在未来作为**异步旁路**引入：
1. **叙事渲染器**：读取历史事件流，让 LLM 生成优美的“人物传记小说”，不干预世界状态。
2. **玩家附身翻译器**：当玩家附身某 NPC 时，将玩家的自然语言输入翻译成结构化的动作事件。

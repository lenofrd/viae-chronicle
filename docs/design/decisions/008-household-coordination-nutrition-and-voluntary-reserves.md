# ADR 008：家庭协作、营养饮食与自愿公共储备

- **状态**：Accepted
- **日期**：2026-11-19
- **适用范围**：跨地点通用机制；溪古镇作为首个落地点
- **相关决策**：ADR 001（事件与 Replay）、ADR 006（劳动效率与食物安全）、ADR 007（人口与家庭）

## 1. 背景

现有模拟已经具备独立的 `HouseholdState`、家庭共享库存、Agent 自主决策、亲缘关系、依赖者监护、公共储备、里正/议事治理、公共服务队列和事件 Replay。但这些机制尚未形成完整的家庭协作闭环：

- ADR 006 原定按安全库存阈值自动从家庭转入公共储备，并由系统自动补给；这会把家庭私产变成系统可强制划拨的资源。
- 当前进食主要按 `food_fields` 顺序消耗单一食物，`daily_meals_per_member` 初值 0.25；没有主食与配餐结构，也没有按周检查营养摄入。
- 当前 `hunger_gain_per_tick`、`hunger_health_damage_threshold` 和 `hunger_health_damage` 将短期饥饿与长期营养/健康问题混在一起。
- `_guardian()` 主要处理未成年依赖者从父母库存进食；Agent 失能后在 `_process_one()` 中停止主动行动，家庭没有普遍照料与代办机制。
- 家庭成员各自按效用选择行动，虽共享库存且已有田块分配，但缺少家庭层面的需求协调、劳动分工和紧急调整。

本决策修正上述制度缺口，同时保留已经实现的生产、交易、家庭生命周期和 Replay 主线。

## 2. 决策

### 2.1 家庭库存与公共储备严格分离

1. 家庭的 `HouseholdState` 库存属于该家庭。系统不得仅因库存超过某个安全天数、容量目标或阈值，就自动扣减家庭资源并转入公共储备。
2. `community_reserves` 是独立的集体库存，不属于任何家庭，也不计入家庭 food-days；公共储备不得被当作家庭库存的隐式扩展。
3. 公共储备的新增来源仅限 Agent/家庭明确、自愿发起并完成的上交行为。当前不引入系统自动征收、按比例摊派、自动采购、凭空生成或生产结算时自动抽成。
4. 上交必须是明确的资源转移：行为主体、物资品种、数量、转出家庭库存、转入公共库存均可追溯；不得超出家庭实际持有量，不得将库存扣成负数。
5. 家庭可拒绝上交。家庭库存高于安全目标不构成上交义务；公共储备不足也不能成为系统强制扣款的理由。
6. 公共储备的容量、损耗和保管规则只作用于公共库存；家庭库存损耗仍按家庭自身既有规则处理。公共库存不得与共享仓储中的家庭寄存余额混同。
7. 公共储备初始值默认为零。若世界开局确需公共库存，必须由开局 Agent/家庭明确自愿上交并写入初始化事件；不得通过世界配置直接注入集体库存。

### 2.2 家庭主动求助与公共储备管理

1. 家庭粮食、水或其他基本生活物资不足时，由家庭成员主动发起求助/申请，不由粮仓扫描家庭并自动发放。
2. 家庭户主可以代表家庭申请；户主失能、死亡、未成年或无法行动时，其他有能力的家庭成员可以代办。家庭成员不必是户主才有求助资格。
3. 申请应说明物资品种与需求数量/期限。申请者依据其可感知的家庭库存和困难提出请求；受理者可核实，不要求 Agent 拥有全知信息。
4. 里正负责日常受理、核实、登记和组织发放；议事会制定公开的救济原则、监督公共账目并处理争议。里正不得把公共储备视为个人财产，也不得绕过库存守恒。
5. 公共储备管理员/仓吏负责实物保管、盘点和出入库记录。初期允许里正兼任日常经办，但申请、审批、实物出库与监督必须保留不同职责记录；不要求当前立即新增独立职业或 Agent 类。
6. 发放以真实库存为上限，可以部分满足、排队、拒绝并说明原因；不得把申请自动等同于批准，也不得把未满足数量静默删除。
7. 对已经失能、昏迷或全家无人能够申请的紧急情况，允许家庭成员以外的居民报告，或里正基于明确的求助/报告事件启动紧急核查。该例外用于避免无人代办造成的死亡，不恢复每日自动扫描和自动划拨。
8. 求助、受理、核实、批准/拒绝、发放、部分满足、申诉和结案均应有可 Replay 的事件记录。具体事件名优先复用现有事件命名风格，实施时不得仅修改内存库存而不留事件。

### 2.3 日常饮食：主食与配餐

1. 一顿正餐由主食和可选配餐组成。主食是基本能量来源；配餐用于提供多样化营养。
2. 当前 `grain` 是主食的主要库存字段；`vegetable`、`meat`、`fish` 是配餐来源。实现优先复用现有字段，不为同一物资另建平行库存。
3. 正餐不能再简单地把 `food_fields` 当作四种完全等价、互相替代的食物顺序。缺少主食时，只有明确配置为可替代主食的食物/食谱才可顶替；鱼肉蔬菜不能默认等价替代粮食。
4. 肉类、鱼类、蔬菜不要求每顿齐全，也不要求每类每天都出现；应按周或滚动七日窗口统计摄入。家庭可根据季节、生产和库存安排配餐。
5. 每周营养目标应分别覆盖蔬菜类和动物性食物来源（肉/鱼可按营养等价折算），目标值与折算系数由地点配置并经长程模拟校准，不在本 ADR 固定具体克数或资源单位。
6. 连续多个统计窗口未达到营养目标，才逐步造成相应健康影响；短期一两顿缺菜、缺肉不应直接扣健康。营养不足与饥饿是不同原因，应能分别诊断。
7. 食物消费必须扣减家庭实际库存并写事件；周摄入统计可由消费事件投影/滚动窗口计算，不应再造一套与库存不同步的营养库存。

### 2.4 饥饿与健康

1. 饥饿表示短期未进食状态；营养不足表示较长时间饮食结构不均衡。两者不得共用同一个阈值和损伤计数。
2. 正常成年人漏掉一天正餐不应因此立即失能或承受严重健康损失。短期饥饿可以增加不适和进食动机，持续多日严重缺食才逐步产生健康损害。
3. 重新校准 `hunger_gain_per_tick`、`eat_hunger_reduction`、`hunger_health_damage_threshold`、`hunger_health_damage` 时，必须联合检查初始饥饿值、每日正餐安排、未成年人份额、用水条件和失能宽限期；不能只改单个阈值。
4. `daily_meals_per_member` 是家庭库存规划参数，不再以 0.25 餐/人/日代表实际饮食制度。新的规划口径应与每天一顿主食正餐和配餐目标一致；该参数迁移前须同步更新 food-days、公共申请量和相关测试。
5. 饥饿伤害应有渐进/持续性，不得在刚跨越阈值后以过大的固定日损伤造成短期断粮即死亡。具体曲线属于地点参数，须以多 seed 长程测试校准。

### 2.5 家庭照料与紧急代办

1. 家庭是共同生活和互相依赖的社会单位，不只是共享库存的账户。共同居住成员之间应根据亲缘/关系、义务、共同生活和现实能力产生照料行为。
2. 照料对象包括失能者、患病/受伤者、幼儿及需要帮助的老人；照料内容按当前模型能力包括喂食、送水、协助基本恢复，以及向外求助/代办。
3. 照料者必须是存活且有行动能力的 Agent；照料会占用其 TU/行动机会，必要时影响生产劳动。不能在不消耗时间、不扣减库存的情况下远程恢复他人。
4. 照料优先级综合对象紧急程度、关系/亲缘义务、同住情况、照料者能力与当前任务。不得假定所有家庭成员无条件互相关心，也不得把家庭关系简化为自动全员照料；关系疏远、冲突、能力不足或自身危机均可导致照料失败。
5. 家庭成员可代失能户主申请公共救济。若家庭内无人可行动，允许邻里/里正紧急报告作为兜底。
6. 不另建第二套 Agent 或 Household 状态机。优先复用 `AgentState`、`HouseholdState`、现有亲缘/认知关系、`_guardian()` 的依赖者逻辑和行动/TU 机制；逐步扩展其适用范围。
7. 失能者不能执行普通主动行动的既有门控继续有效；照料由其他 Agent 执行，不能通过让失能者继续运行普通决策循环来规避门控。

### 2.6 家庭协商与劳动分工

1. 家庭每天/关键事件后形成轻量家庭计划，协调基本任务：饮食与取水、耕作/采集等生计、照料、对外求助、必要家务。
2. 家庭计划不是对成员的绝对命令。成员依据年龄、健康、技能、体力、位置、TU、个人意愿和社会角色评估是否接受；可拒绝、无法完成或因突发事件调整。
3. 分工应避免重复投入和关键任务无人承担，例如多人同时做低优先级工作而无人取水/照料；同时保留成员自主性，不把家庭变成单一中央控制 Agent。
4. 优先复用现有田块分配、工作地点、行动效用和 household 成员关系；家庭计划是协调层，不复制生产、库存或个人行动状态。
5. 协商可先采用确定性、低成本的规则（提出需求、比较成员能力/可用时间、形成任务建议、个人接受/拒绝），不要求引入 LLM、复杂谈判模型或新的完整心理状态机。
6. 分工决定、接受/拒绝、任务完成和计划调整应有事件/可重建投影。不得只在每个 tick 无记录地重排家庭成员工作。

### 2.7 家庭储存：当前不设容量上限，预留建筑接口

1. 当前阶段家庭库存不设置固定容量上限，也不按家庭人口、库存天数或建筑面积自动限制可持有数量。
2. 当前不因所谓“超出安全容量”自动损耗家庭粮食、布匹、鱼、肉、蔬菜或饮水；也不得自动出售、借出、转存、共享或转入公共储备。
3. 保留建筑储存能力接口，供后续地窖、粮窖、储物棚、住宅储藏空间和扩建系统接入。届时容量应由建筑类型、实际建筑等级/面积和储存设施共同决定，并按物资类型区分；本决策不预设具体数值。
4. 建设或扩建储存空间必须遵守 ADR 005 的土地权利与审批制度，并真实消耗材料、劳动力和施工时间；不得因库存增长自动生成地窖或扩建。
5. 家庭自愿将物资寄存在共享仓储时，寄存余额仍属于该家庭；共享仓储不等于公共储备。公共储备只接受本 ADR 2.1 所述的明确自愿上交。
6. 未来若启用容量约束，超限后的出售、转存、扩建或其他处理应由家庭/Agent自主选择并记录事件；不得由系统替家庭处分资产。

### 2.8 家庭成员的责任边界

1. 家庭共享库存意味着家庭成员可以在现有家庭经济规则下消费和共同安排物资，但不意味着每个成员都能任意代表家庭向公共储备上交。
2. 对外上交应由户主或家庭明确授权的成员发起；授权和上交数量须可追溯。成员不能因系统便利而被默认强制捐献家庭资产。
3. 家庭内部协商不能绕过家庭间交易、借贷、土地租赁、婚姻财产转移和继承规则；这些继续使用各自既有契约与事件。

## 3. 与现有主线的兼容要求

1. 保留 `HouseholdState` 作为家庭资产、债务与成员归属单位；不新建家庭库存类，不把家庭资产并入公共储备。
2. 保留现有家庭交易、实物借贷、共享仓储的家庭独立余额、土地租约、婚姻成员迁移、彩礼/陪嫁、出生、分家、继承和债务结算语义。
3. 保留 `community_reserves` 作为公共库存字段；改变的是其入库来源和出库流程，不是删除公共储备或将其改成家庭库存。
4. 现有自动转存/自动补给逻辑必须停止作为新规则执行。旧事件仍须可 Replay；不得在 Replay 时按新规则重新解释历史事件。
5. 若已有世界/测试依赖旧的自动转存，迁移时应显式调整测试与初始化场景：旧库存快照按原有所有权保留，不能在升级时无事件地把已存在的公共库存退回家庭或反向划拨。
6. 保留 `food_fields` 等已有配置字段作为迁移兼容入口；新餐食结构应先在既有配置/schema 上扩展或明确映射，再逐步废弃旧的等价替代语义。不得直接删除字段导致所有世界配置失效。
7. 保留 `_guardian()` 对未成年人的既有行为；新增成年失能者照料时抽取/复用通用照料能力，避免破坏当前依赖者进食测试。
8. 保留 `_process_one()` 对失能者停止自主行动的门控；由照料者行动解决，不得让失能者重新执行普通动作。
9. 保留现有 TU、移动、体力、劳动预算、生态资源守恒和事件 Replay。家庭协商/照料必须占用现有行动时间，不另造时间系统。
10. 任何状态变化均以事件记录并支持 Replay；投影按事件 after 快照重建，不在 Replay 中重新执行申请审批、家庭协商或营养判断。

## 4. 分阶段落地顺序

1. **公共储备所有权修正**：停用家庭自动转存；保留现有公共库存；加入 Agent 自愿上交与事件守恒测试。
2. **家庭求助闭环**：申请、里正受理、核实、批准/部分发放/拒绝、出入库事件；支持户主失能时家庭成员代办。
3. **餐食与饥饿调整**：主食+配餐、日常一顿正餐、营养滚动窗口、渐进饥饿伤害；同步更新 food-days 和配置注释。
4. **家庭照料**：先实现同户 Agent 对失能/依赖成员喂食送水，再扩展伤病与邻里紧急报告。
5. **家庭分工协商**：先覆盖取水、食物生产、照料和求助等关键任务，再扩展家务与其他生计。
6. 每个阶段先补单元/Replay 测试，再跑常规 pytest；所有阶段完成后跑多 seed 长程模拟，比较人口、饥饿死亡、营养缺乏、家庭劳动分配、公共储备和求助结果。

## 5. 验证标准

- 家庭库存超过任何安全天数都不会自动减少；无 Agent 上交事件时，公共储备运行中不会增加。
- 上交数量守恒、不可超额、可拒绝、Replay 正确；共享仓储的家庭寄存余额不会进入公共储备。
- 申请不会自动出库；只有批准/紧急救助并完成发放事件后，公共库存减少、家庭库存增加；库存不足时支持部分满足且不为负。
- 户主失能时，其他有行动能力的家庭成员可代申请；全家失能时可由外部报告启动紧急核查。
- 每顿正餐包含主食；配餐可以缺项；连续七日窗口检查蔬菜和肉/鱼摄入；短期缺少某种配餐不立即扣健康。
- 正常成年人漏掉一天正餐不会因此直接失能；持续严重缺食才产生渐进健康损失。
- 同户照料消耗照料者行动时间和家庭真实库存；失能者本人仍不执行普通行动。
- 家庭任务安排能减少重复劳动和关键任务空缺，同时允许成员拒绝/失败；所有决定可追踪、可 Replay。
- 既有出生、婚姻迁移、分家、继承、租约、交易、借贷、生态、TU 和 Replay 测试不回归。

## 6. 不在本决策中固定的事项

- 各年龄段每日餐量、主食单位、配餐份量和每周营养目标具体数值。
- 蔬菜、肉、鱼的营养等价换算及缺乏症健康曲线。
- 饥饿曲线、伤害宽限期和不同年龄/健康状态的参数。
- 里正是否长期兼任仓吏、未来专职仓吏数量与任用方式。
- 家庭协商频率、分工权重、关系影响系数和拒绝概率。
- 邻里救助范围、紧急报告触发阈值及议事会申诉时限。

# ADR 009：自然环境与人文系统的分层及领域边界

- **状态**：Accepted
- **日期**：2026-11-20
- **修订**：2026-11-21 田块生态状态归属与自然产出跨域转移边界（§2.3、§2.4、§2.5、§2.6、§7）；2026-11-21 P4 世界生成分段落地回写（§3 落地注记、§2.4 表增补）；老板裁决见 `.ai/DECISIONS.md`
- **适用范围**：跨地点通用架构；溪古镇（Brookvale）作为现有落地点
- **决策主题**：自然环境的动物 / 植物与无机环境拆分，以及自然环境、人文系统与世界内核之间的分层

## 1. 背景与上下文

现有自然环境设计已经包含地形、气候、水文、土壤与田地、植被、动物、灾害、演化机制和状态记录等子系统，并定义了子系统间的依赖关系。但随着世界范围扩大到深山、大河流域、平原和多个聚落，单纯按功能增加子系统容易造成新的耦合：

- 动物、植物、地形、水文和气候可能互相直接读取或修改内部状态；
- 人类生产活动可能绕过环境规则，直接修改资源库存；
- 自然环境与人文社会可能共享数据结构，却没有明确状态所有权；
- 世界生成、领域演化和跨领域交互容易混在同一模块中；
- 为拆分模块而重复建设时间、空间、实体、事件、调度或寻路基础设施。

本决策确立稳定的分层和领域边界。目标不是一次性重写现有代码，而是为后续自然环境扩展和渐进迁移提供统一约束。

本决策遵循既有事件溯源、确定性模拟、机制与地点配置分离、复用现有基础设施的架构原则。

## 2. 决策

### 2.1 总体采用分层架构

系统按职责划分为以下逻辑层。它们是架构边界，不要求一层对应一个 Python 包、目录或类。

1. **基础设施层（World Kernel）**
   - 提供统一逻辑时间、Tick、实体 ID、空间索引、事件流、状态投影、确定性随机数、调度和通用序列化能力。
   - 继续复用现有 `World`、`WorldState`、Scheduler、EventLog、SpatialConfig、SpatialIndex 等基础设施。
   - 不包含气候、繁殖、婚姻、采集等具体领域规则。

2. **领域层（Domain Modules）**
   - 自然环境和人文社会分别作为独立领域，各自拥有自己的状态、规则和生命周期。
   - 每个领域只负责自身状态的验证、演化和事件处理。
   - 领域之间不得直接写入对方的内部状态。

3. **领域子系统层（Domain Subsystems）**
   - 领域内部按专业职责拆分子系统，例如气候、水文、地形、土壤、植物生长、动物繁殖、动物行为、人口、家庭、农业和治理。
   - 子系统声明依赖的输入、产生的输出、状态所有权及调度阶段。
   - 子系统之间遵循单向依赖；禁止通过互相调用形成循环依赖。

4. **跨领域契约层（Domain Contracts）**
   - 对外提供稳定、最小化的查询接口、命令接口和事件契约。
   - 查询接口提供只读快照；命令表达请求或意图；事件记录已经发生且通过验证的状态变化。
   - 契约层不持有领域库存，不代替领域作出领域规则判断，也不成为第二套状态存储。

5. **世界协调层（World Orchestration）**
   - 由统一 Scheduler / World 驱动各领域和子系统，明确阶段顺序、同 Tick 因果关系和事件处理时机。
   - 协调层负责何时运行，不负责替领域计算具体规则。
   - 各领域不得自行创建独立时钟或独立 Tick。

### 2.2 自然环境领域拆分为两个顶层模块

自然环境领域由两个并列、可独立演化的顶层模块组成：

#### A. 环境模块（Environment）

拥有植物与无机自然环境状态，内部至少区分以下子系统：

- **地理与地形**：高程、山脉、坡面、河谷、地貌分区、地质基础等相对稳定的空间条件。
- **气候**：季节、温度、降水、风及长期气候变化。
- **水文**：流域、河段、水体、径流、水位、流速、地下水、湿地、水质及水资源变化。
- **土壤**：土壤类型、湿度、肥力、侵蚀、沉积和恢复。
- **植物生态**：野生植物、森林、草地、灌丛、植物群落、生长、繁殖、演替、枯死和恢复。
- **无机自然资源**：矿物、岩石及其他非生物资源的空间分布、可采量和变化。
- **分解与养分循环**：枯落物、尸体和排泄物的分解，以及养分向土壤和水体的回归。真菌、细菌等分解者及其状态归环境模块管理。

环境模块拥有上述状态，并负责验证、结算其变化。植物是生物状态，不应简单等同于木材、草药等可采集资源库存；森林和草地应保留覆盖度、生物量、年龄或生长阶段、更新能力及退化状态等生态属性。

#### B. 动物模块（Wildlife）

拥有动物个体与动物种群状态，内部至少区分：

- **物种与生物基础**：物种定义、个体、年龄、性别、健康、能量和生命周期。
- **种群**：数量、密度、年龄结构、繁殖率、死亡率和种群迁移。
- **行为**：觅食、饮水、休息、移动、迁徙、躲避和捕食。
- **生态关系**：捕食、竞争、寄生、共生及栖息地选择。

鱼类、鸟类、昆虫、野兽等动物均归动物模块管理。河流、湖泊和湿地提供水文条件与栖息地，不直接拥有或代替动物模块管理鱼类库存。

动物可以复用通用实体标识、空间查询、调度、事件和序列化基础设施，但必须使用独立于人类 `AgentState` 的状态模型，不包含人类家庭、婚姻和亲属关系字段。

#### C. 物种多样性与食物网

生态系统必须支持多物种共存及其动态关系，不得只用固定动物名单或单条捕食链表示。

- **物种定义**：物种配置描述食性、栖息地需求、活动与繁殖特征、环境耐受范围及生态关系；物种配置与地点分布配置分离。
- **食物网**：描述植物、动物和分解者之间的取食关系。一个物种可以有多种食物和多个天敌；食物网是跨 Environment 与 Wildlife 的关系模型，不是第三个状态领域。
- **能量流动**：摄食应受食物可用量、摄食能力和能量需求约束；摄入能量用于维持、生长和繁殖，并通过代谢、排泄和死亡损失或转移。不得凭空产生能量或生物量。
- **种群动态**：出生、死亡、捕食、竞争、迁移和资源承载力共同影响种群数量；物种分布由栖息地条件和种群过程决定，不由固定名单强制生成。
- **养分循环**：枯落物、尸体和排泄物经分解回归土壤或水体，供生产者利用。分解过程由 Environment 结算，动物产生的影响由 Wildlife 提交。

食物关系定义由物种配置提供；动物摄食和捕食由 Wildlife 决策，涉及植物、水体、土壤及分解过程的状态变化由 Environment 结算。任何领域不得直接修改另一领域的生物量或种群状态。

### 2.3 人文社会是独立领域

人文社会领域继续拥有其自身状态和规则，例如：

- 人类个体、家庭、人口与社会关系；
- 劳动分工、农业生产、采集、渔猎和手工业；
- 土地、建筑、经济、贸易、治理和文化。

人类生产系统管理人类活动、劳动投入、产出加工、家庭库存和分配；自然环境或动物模块管理自然侧资源及其生态状态。人类活动通过跨领域契约影响自然状态，不因某项活动由人类发起就把自然状态所有权转移给人文系统。

田块生态状态（田块长势、田块地力等）归环境模块拥有并结算：人文社会提出农业操作意图，经跨领域契约由环境模块校验并结算田块侧变化，不因农事由人类发起就把田块生态状态划归人文系统；产量换算、收成入家庭库存与季节劳力簿记归人文领域。野生植物群落同样归环境模块。二者通过土壤、水文、气候和生态影响契约交互，不重复持有同一份状态。

### 2.4 状态唯一所有者

每类可变状态必须有且只有一个负责写入和结算的领域：

| 状态 | 所有者 |
|---|---|
| 地形、气候、水文、土壤、水体 | 环境模块 |
| 野生植物及植物群落 | 环境模块 |
| 田块长势与田块地力（田块生态状态） | 环境模块 |
| 矿物及非生物自然资源存量 | 环境模块 |
| 真菌、细菌等分解者及分解过程 | 环境模块 |
| 动物个体、鱼群及其他动物种群 | 动物模块 |
| 鱼 / 猎物存量池（P4 阶段性：池形式归动物域，P5 升个体 / 种群） | 动物模块 |
| 植被类生态资源池（柴薪 / 草药硬木等）与资源池生成目录 | 环境模块 |
| 人类个体、家庭、人口和社会关系 | 人文社会领域 |
| 家庭库存、生产活动、交易与分配 | 对应人文经济 / 生产子系统 |
| 农业操作意图、劳动投入与季节劳力簿记 | 人文社会领域 |

其他领域不得直接修改所有者的内部状态。跨领域变化必须提交命令或意图，由状态所有者验证并结算；成功的变化进入统一事件流，并更新相应状态投影。

“资源服务”可以作为统一调用入口，但它只是按资源类型路由到对应状态所有者的门面，不得把所有自然资源和生物资源搬进一个中央库存，也不得绕过动物模块直接扣减鱼群或动物数量。

### 2.5 跨领域契约

跨领域交互优先收敛为以下契约。具体类名和函数签名由后续接口设计确定，本 ADR 不冻结实现细节。

- **SpatialQuery**：读取空间单元、邻接关系、可达性和通行成本；复用现有 SpatialIndex 与 Dijkstra，不新建地图或寻路系统。
- **EnvironmentQuery**：读取指定空间单元和时间点的环境只读快照，例如温度、降水、土壤湿度、水文条件、植物覆盖和栖息地条件。
- **ResourceService**：统一提交资源获取、消耗或预留请求，并将请求路由给实际拥有该资源状态的领域。服务本身不拥有资源库存。
- **WildlifeQuery**：为狩猎、观察等活动提供动物或种群的只读查询，不允许调用方直接修改动物状态。
- **FoodWebQuery**：只读查询物种的食物、捕食者及营养级关系；不拥有生物状态，不执行摄食或资源结算。
- **EcologicalImpact**：提交采伐、踩踏、啃食、捕捞、污染、开垦、耕耘、排水等影响意图，由相应状态所有者验证并结算。

接口应表达调用方意图和必要上下文，不暴露对方内部状态结构。查询返回只读数据；命令的结果应能区分接受、拒绝和实际结算结果。已发生的状态变化必须有事件记录和因果来源。

### 2.6 依赖方向与交互规则

1. 环境模块向动物模块提供环境条件、资源可用性和栖息地快照；动物模块不得直接修改环境内部状态。
2. 食物网关系由物种配置定义；动物模块依据食物可用性和能量需求执行摄食、捕食及竞争。动物数量由 Wildlife 结算，植物数量与生物量由 Environment 结算。
3. 动物模块通过事件或生态影响契约表达啃食、踩踏、排泄等影响；环境模块按自身规则处理涉及植物、土壤和水体的变化。
4. 环境模块提供水体、植被和栖息地条件；动物模块根据这些条件决定动物生存、移动和繁殖。
5. 人文社会通过查询和命令使用自然资源；不能直接读取或改写自然领域内部字典。
6. 捕鱼属于对动物种群的捕捞行为，鱼群数量由动物模块负责结算；水质、水位和河流状态由环境模块负责。捕获成功后渔获转入人文域家庭库存，由人文领域结算入库。
7. 同一交互不得在调用方和状态所有者两侧重复扣减或重复产生资源。命令受理、资源结算和事件记录必须具有明确的一致性边界。
8. 领域之间不得互相导入对方的内部状态类作为写入手段；共享的只能是基础设施类型和公开契约。
9. 采集、狩猎、捕捞成功即跨域转移：自然侧存量由原所有者结算减量，产出转入人文域家庭库存，由人文领域结算入库；转移以成功事件为界。
10. 农事操作由人文社会提交操作意图；田块长势与田块地力由环境模块校验并结算，产量换算、收成入家庭库存与季节劳力簿记由人文领域结算。

### 2.7 确定性调度与因果顺序

所有领域共用世界 Tick 和统一 Scheduler。具体阶段可按模型需要细化，但必须显式声明依赖和同 Tick 顺序。

初始建议顺序如下：

1. **基础自然条件演化**：气候、水文、土壤等环境驱动变量。
2. **环境生态演化**：植物生长、更新、退化及自然资源变化。
3. **动物生态演化**：动物依据食物网觅食、捕食、竞争、饮水、移动、繁殖和死亡；摄食结果由相应状态所有者结算。
4. **人文社会活动**：人类感知、决策、劳动、生产、采集、狩猎和建设。
5. **跨领域影响结算**：处理本 Tick 已受理的生态影响请求，并按状态所有者结算。
6. **投影与观察**：更新查询快照和观察层所需数据。

上述顺序是初始调度约定，不意味着所有模型只能按固定顺序运行。后续可根据具体因果需求调整阶段，但必须避免隐式循环调用、同 Tick 重复消耗和不确定事件排序；涉及前后阶段的行为必须有明确规则。

## 3. 世界生成边界

自然环境生成与聚落 / 社会生成在职责上分离：

1. 自然环境生成负责地理骨架、流域、地貌、气候带、土壤、植被和自然栖息地，并依据地点环境与确定性种子生成适宜的物种分布。
2. 聚落生成读取自然环境的公开结果，决定聚落位置、道路、建筑、田地和初始家庭。
3. 聚落生成不得反向决定或覆盖自然地理骨架；人类活动造成的后续环境改变必须通过正常领域接口和事件发生。
4. 固定的溪古镇核心地理锚点与可变的外围世界应由世界生成配置和确定性种子共同约束，不能依靠无约束分区拼接破坏河流、山脉和流域连续性。
5. 世界生成应复用既有空间节点与边，不创建平行空间图。

**P5-d 落地注记（2026-11-21）**：`modules/agents.py`（约 4390 行）未整体改名搬迁，而是按职责拆入 `domains/society/agents/` 子包——`module.py` 只保留 `AgentModule` 与日结算调度顺序（`step`/`_settle`/`_log_agent_error`），业务方法按 mixin 归口：`lifecycle`（衰老/死亡/日内推进）、`labor`（分工计划）、`decision`（感知打分选择）、`actions`（动作执行与还债）、`household`（日常接触/用水）、`market`、`mortality`（死亡继承）、`marriage`、`reproduction`（分家生育）、`debt`（催收纠纷）；纯函数与数据类独立成 `perception`、`production`、`spatial`、`demographics`、`constants`。模块注册名仍为 `agents`，`modules/` 包已删除、旧路径 import 一次改净。D1/D2 随拆分消除（施工/治理改依赖 `agents.demographics.age_years`），D3 仍待 P6；状态所有权登记同步细分到子模块（`tests/test_architecture_boundaries.py`）。两年基线（seed 20261118，720 tick）与 P5-c 工作区逐字段 identical。

**P6 落地注记（2026-11-21）**：领域状态模型归各领域——`domains/environment/state.py`（地形/水源/生态容器）、`domains/wildlife/state.py`（鱼/猎物池容器 + 资源类型归属）、`domains/society/state.py`（人物/家庭/土地/建造/治理）；`core/state.py` 只剩 `WorldState` 组合根（§2.1 基础设施职责，架构测试显式豁免组合根的唯一 core→domain 导入），跨领域共享值对象落到 `core/snapshots.py`（`ClimateSnapshot`，契约查询返回的只读快照）与 `core/pools.py`（`ResourcePoolSpec`/`ResourcePoolState`，环境域与动物域共用）。家庭访问器从 `core/household.py` 迁入 `domains/society/households.py`（其操作对象是人文状态）。**回放归属（2026-11-21 老板裁决，取代同日「迁入 world」的临时做法）**：`core/replay.py` 只保留通用引擎（事件读取、事件顺序、按 `_on_<event_type>` 派发、`finalize`/`validate` 钩子），不含任何 `vale.domains.*` 导入；领域事件投影由 `domains/environment/projection.py`、`domains/wildlife/projection.py`、`domains/society/projection.py` 各自提供；`world/replay.py` 只做注册组装并对外暴露 `rebuild_state`。这样 core 不依赖具体领域，基础设施能力也不上移到协调层。架构闸新增三条：领域状态模块不得导入其他领域；`core/state.py` 只允许 `WorldState`；引擎领域无关且三投影由 world 组装。两年基线（seed 20261118，720 tick）与 P5-d 工作区逐字段 identical。

## 4. 配置与实现约束

1. 遵循 ADR 003：通用机制与地点配置分离；通用规则进入系统机制，地点物种分布、栖息地参数和资源条件进入对应 location 配置，并使用 Pydantic 校验。
2. 动态状态变化事件化，统一进入现有 EventLog；状态投影不得成为第二个真相源。
3. 保留确定性、可重放和因果链；随机过程使用统一确定性随机机制。
4. 复用现有时间、空间、事件、调度和实体基础设施，不另建平行实现。
5. 自然环境各子系统继续沿用现有 `systems/natural-environment/` 文档体系；本 ADR 不要求为了层次名称重排目录。
6. 模块边界是逻辑边界，不要求将整个环境模块写成单一大类，也不要求把每个子系统都拆成独立运行时模块。

## 5. 迁移原则

本决策不授权一次性重写自然环境或人文系统。迁移必须分阶段、最小改动并保持现有行为可验证：

1. 先审计现有 `WorldState`、`ClimateModule`、`EcologyModule`、`AgentModule`、`world/xigu.py`、资源操作和 Scheduler 的真实读写关系。
2. 建立状态所有权清单、子系统依赖图和公开契约；标出当前违反边界的直接读写。
3. 拆分顺序为：先按领域拆出状态容器，再抽出只读查询，最后收敛写入。原「先抽查询」的顺序已于 2026-11-20 由老板裁决取代（见 `.ai/DECISIONS.md`）：在扁平 `WorldState` 上先建查询，会为了取数直接读所有领域字段，等于把耦合固化进新 API；容器先分，查询才有明确的读边界。
4. 将 `world/xigu.py` 中自然地理生成与聚落生成职责逐步分离，保留现有世界生成顺序和溪古镇兼容性。
5. 在动物模块实现前，审查现有 Agent 执行基础设施，复用可复用部分；不复制整套人类 Agent，也不强行继承人类状态模型。
6. 每一步保留或补充确定性、事件守恒、Replay、空间连续性和长程生态测试；不得通过删除实质断言或缩短长期测试来宣称迁移完成。
7. 不因本 ADR 自动移动大量文件、修改配置路径或改变既有领域行为。具体迁移方案应单独审查和分阶段实施。

## 6. 后果与影响

### 优势

- 动物、植物与无机环境、人文社会的状态所有权清楚，降低跨领域耦合。
- 自然环境可以在没有人类聚落的区域独立演化；人文系统可以替换地点而不重写自然模型。
- 动物作为生物实体而非资源池管理，能够表达繁殖、迁徙、捕食和种群变化。
- 统一基础设施与跨领域契约避免重复建设时间、空间、事件、寻路和调度系统。
- 分层允许逐步提高模型精度，并支持不同空间尺度的模拟。

### 代价与风险

- 需要维护稳定的跨领域契约和状态所有权清单。
- 领域命令与事件结算增加了接口设计和调度复杂度。
- 过度抽象可能形成庞大的通用资源服务或事件总线；必须保持契约最小化，领域规则仍由状态所有者负责。
- 动物个体模拟与远程种群聚合可能需要混合精度策略，具体精度和性能预算留待后续设计。
- 现有代码尚未必满足本决策的全部边界；本 ADR 定义目标架构，不代表实现已经完成。

## 7. 不在本决策中固定的事项

- 各子系统最终的 Python 包路径、类名、函数签名和文件拆分方式。
- 环境快照、动物状态、生态影响命令的完整字段 Schema。
- 各领域具体 Tick 频率、子阶段和异步 / 聚合计算策略。
- 动物个体模拟与种群聚合的切换阈值。
- 物种目录、物种参数、食物网具体关系及能量 / 养分计算公式；这些内容由后续系统与地点设计确定。
- 人工林、养殖动物等其余受人类持续管理对象的完整归属细则（农作物田块生态状态的归属已于 2026-11-21 修订明确，见 §2.3、§2.4）；后续系统设计须遵循状态唯一所有者原则。
- 自然资源采集权限、保护区制度和具体地点习俗参数。

## 8. 与其他决策及文档的关系

- 遵循 ADR 001：状态变化以事件记录并支持 Replay。
- 遵循 ADR 002：核心模拟由确定性规则驱动，不依赖 LLM 实时推理。
- 遵循 ADR 003：系统机制与地点配置分离。
- 本决策细化 `docs/design/systems/natural-environment/00-overview.md` 的自然环境子系统边界与依赖方向；原有空间骨架、气候、水文、地形、土壤、植被、动物、灾害、演化机制和状态记录文档继续有效，若与本决策冲突，以本决策确立的领域边界和状态所有权为准。
- 具体模块接口、状态模型、迁移步骤和地点参数由对应 systems / locations 设计文档后续细化。

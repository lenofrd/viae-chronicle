# 迁移对应与分步计划（migration-plan）

- **对应任务**：TASK-01 第 6 项
- **依据**：ADR 009（`c9f29a5`）+ 本目录另外四份审计
- **性质**：计划，不含代码改动。阶段一是只读审计。

## 1. 当前实现 → ADR 目标 对应关系

| 现行实现 | 实际职责 | ADR 目标归属 | 迁移动作 | 难点 |
|---|---|---|---|---|
| `ClimateModule` | 天气、季节、水位比例、灌溉档 | Environment（气候/水文） | 保留模块，水位归入水文子系统；增加水源节点库存以支撑取水 | 水文目前只有单标量，没有空间分布 |
| `EcologyModule` | 资源池初始化与再生 | Environment（植被/无机）+ Wildlife（鱼/猎物） | 池按 `resource_type` 拆分：植物类归环境，鱼与猎物归动物 | 运行时池无生物量/退化字段；`game_trail` 与 `hunt` 错配 |
| `AgentModule`（217KB） | 人口、家庭、劳作、经济、社交、并调度环境/土地/建造结算 | Human（多个子系统）+ 协调层 | 按动作类型与结算阶段拆分；采集/取水/野遇改走契约；环境结算移出 | 体量最大；`_settle` 内隐含跨域写；RNG 与事件顺序耦合 |
| `modules/environment.py` | 人文社区服务（维护、需求、储备、效率） | Human（社区/公共资源） | 更名（如 `community.py`），并入人文域；与 ADR 的 Environment 消歧 | 与 agents 双向调用，且被 22 项测试直接依赖 |
| `modules/land.py` | 地块初始化、转移、继承、用途 | Human（土地制度） | 保留为人类子系统；初始化数据来自 Environment 的公开结果 | 与 `terrain_cells` 存在两份肥力 |
| `modules/construction.py` | 建造配方、推进、修缮 | Human（建设） | 保留；去掉对 `agents.age_years` 的导入 | 生产路径无触发者 |
| `modules/governance.py` | 选举、议事、申诉 | Human（治理） | 保留；去掉对 agents 的依赖 | 生产路径无调用者 |
| `modules/tenancy_economy.py` | 租约、借贷、集市、公共仓储 | Human（经济） | 保留；把 `building.attributes` 里的库存提升为正式状态 | 库存藏在 attributes |
| `modules/social.py` | 认知、记忆、亲缘 | Human（社会关系） | 保留；把回放所需默认值改为事件可推导 | 回放反向依赖 |
| `core/replay.py` | 事件重建状态 | 内核（投影） | 去掉 `import modules.social` | 需要事件携带足够信息 |
| `worldgen/xigu.py` | 自然地理 + 聚落/人口 + 资源池 | 拆为 Environment 生成与 Human 聚落生成两段 | 先定义"自然环境公开结果"对象，再让聚落生成只读它 | 当前同一文件、同一函数链 |
| `SpatialNode.attributes` 中的资源字段 | 资源池的第二份副本 | 归各自所有者，attributes 只留静态属性 | 生成后不再复制资源池字段 | 观察层与测试可能依赖 attributes |

## 2. 阶段顺序（2026-11-20 已裁决）

裁决接受：**先拆状态容器，再建查询，最后收敛写入**，取代 ADR 009 §5.3 的查询先行。理由：在扁平 `WorldState` 上建的查询函数会为了取数而直接读所有领域字段，等于把耦合固化进新 API；容器先分，查询才有明确的读边界。P0 已同步修订 ADR §5.3。

| 阶段 | 目标 | 主要改动 | 验收 |
|---|---|---|---|
| P0 基线加固 | 让边界可失败 | 新增架构测试：所有权 allowlist、导入边检查、配置一致性（`hunt` 目标池类型、肥力口径）、空资源池与未消费物资的告警测试；同步修订 ADR 009 §5.3 | `pytest -q -m "not long_run"` 全绿；新增测试在人为越界时能红；ADR 与台账一致 |
| P0.5 命名消歧（已完成） | 先消除同名 | `modules/environment.py` 已更名 `modules/community.py`，只改名称与导入，未改断言 | 全量测试绿；`grep` 无旧名残留（除历史文档） |
| P1 状态容器拆分（已完成） | 一域一容器 | `WorldState` 变为组合根：`environment` / `wildlife` / `human` 子容器；字段按表迁移；`building.attributes` 库存提升为状态；肥力按裁决落为 `fertility_factor`（动态 1.0）与 `soil_quality`（静态生成值） | 全部现有测试不改断言仍绿；回放重建结果与拆分前逐字段一致；两年基线数字不变 |
| P2 只读查询（已完成） | 读侧收口 | 新建 `vale/contracts/queries.py`：`EnvironmentQuery`（气候、灌溉系数）、`SpatialQuery`（节点、田地、面积）、`WildlifeQuery`（只读视图，P5 填充）；删除 `agents` 内三个私有读函数与散落气候直读；架构测试新增「人类模块直取环境字段即红」，农事四字段豁免、两处未收敛访问登记台账 | 人类模块不再 import 环境内部数据结构；查询有单元测试（6 项）；两年基线逐字段不变 |
| P3a 水文库存（已完成） | 先有源 | 新增 `EnvironmentState.water_sources`（容量/存量/再生/日抽上限）与 `vale/contracts/water.py` 取水结算；每 tick 由 climate 按水位补水；`collect_water` 改走结算，未配置水源的节点保持旧行为；新增 4 类水源事件与回放处理器 | 取水行为与现基线逐 tick 等价（1226 次、29,424 单位、0 拒绝）；库存守恒测试；坏配置启动报错 |
| P3b 写入契约（已完成） | 写侧收口 | 新增 `vale/contracts/resources.py`（`ResourceService.harvest` 校验存量与同 tick 额度、先事件后投影、拒绝事件；`withdraw_water` 路由 P3a 水源）与 `vale/contracts/impacts.py`（`EcologicalImpact` 洪涝/旱灾/滑坡/野遇）；`agents._execute_gather`、`agents.collect_water`、`xigu_events` 四类影响改走契约，台账清零 | 架构测试跨域写为 0（`KNOWN_CROSS_DOMAIN_WRITES` 清空）；采集守恒（池减 = 家庭增）、额度/空库存拒绝、四类影响投影与回放重建测试；两年基线逐字段不变 |
| P3c 契约所有权修正（已完成） | 契约只路由 | 裁决①（P3b 把 contracts 登记为写入者偏离 ADR 009 §2.4）：结算/校验/事件从契约移交领域所有者——采集结算入 `modules.ecology.harvest_from_pool`，水源结算入新 `modules/hydrology.py`（`contracts/water.py` 移除，climate 补水改直调），长势/地力/人物健康结算入 `modules.agents.apply_*`；`ResourceService` / `EcologicalImpact` 改为纯路由门面；架构测试新增红线「contracts 不得出现在状态写入者集合」，撤销 contracts 的写入者登记 | 纯重构行为等价：两年基线逐字段一致（含全部事件类型计数）；全量测试绿；红线测试可失败性已验证 |
| P4 世界生成分段 | 自然先、聚落后 | 生成自然环境公开结果（地形、水系、气候带、土壤、植被、栖息地）；聚落生成只读；统一资源模型，取消 attributes 复制；`game_trail` 与猎物绑定；`soil_quality` 由生成输入写入 Environment | 同种子生成结果逐字段等于现基线（除有意修正的错配）；`test_xigu_worldgen` 扩充 |
| P4.5 生产接入（三个独立任务） | 让测试专用子系统真正运行 | 顺序：治理 → 建造 → 社区储备。治理先接生产，因为建造与租约读 `council_decisions`；建造是硬木/铜钱消耗端；储备依赖公库与仓房。每个任务单 PR | 每个任务接入后重跑两年基线并更新 STATUS；资源消耗端可观测；原有测试仍绿 |
| P5 动物状态 | 真种群 | 动物独立状态模型；先抽通用执行能力（实体 ID、生命周期调度基础、确定性随机），再做尺度分层（近处个体、远处聚合、进入互动区个体化）；食物网查询；性能预算与聚合阈值 | 新增动物生命周期与尺度切换测试；切换事件可回放；长程无 `agent_error`；性能不低于现基线 |
| P6 人文内部与调度 | 拆分大模块 | 把 `AgentModule` 的结算阶段拆为独立 Human 子系统；调度改为 ADR §2.7 六阶段 | 六阶段顺序测试 |

## 3. 已裁决口径（2026-11-20）

1. **状态数据形状可以改变**：子容器会改变 `WorldState` 的属性路径；P1 允许动访问路径，但不改行为。
2. **肥力**：Environment 同时持有 `fertility_factor`（动态、默认 1.0、灾害扣减、参与产量）与 `soil_quality`（静态、来自地形生成、不参与产量）；`terrain_cells.soil_fertility` 仅作生成输入。
3. **取水**：P3a 先建水源库存（容量按现量标定、两年基线内不触顶），P3b 再改走契约；稀缺化另立平衡任务。
4. **三个子系统**：治理、建造、社区储备均为正式目标，排在 P4 之后，顺序治理 → 建造 → 社区储备，各自单 PR、各自刷新基线。
5. **迁移顺序**：容器 → 查询 → 写入，P0 同步修订 ADR。

仍未定的（不阻塞 P0）：
- 动物任务的性能预算与"个体/聚合"切换阈值，在 P5 设计时给出。
- 三个接入任务是否改变两年基线的可接受范围，需在首个接入任务前定口径。

## 4. 每阶段的测试要求

- 不得删除现有实质断言；不得缩短长程测试来宣称完成（ADR §5.4）。
- 跨域写收敛必须由**会失败的测试**守护，而不是靠代码评审。
- 每个新契约（查询/命令）都需要：正常路径、拒绝路径、同 tick 幂等、回放重建、坏配置启动报错。
- 长程基线目前只有 1 项（2 年 720 tick），P1、P3b 与 P4 完成后应恢复一项 40 年 seeded 长程作为回归门禁；恢复前需老板批准时间预算。
- 性能基线：本次基线为 548 项 869 秒；P5 引入动物后必须重新记录，不得只报功能通过。

## 5. 回滚与提交策略

- 每阶段一个分支、一个 PR，阶段间不合并未完成的分支。
- P1 的容器拆分应可在单次提交内回滚，不与查询层改动混在同一 PR。
- P3a/P3b 新增事件类型后，旧事件库回放测试（`pytest -k replay`）必须仍绿；不兼容时写显式迁移说明，不做静默降级。

## 6. 与 ADR 不一致处清单

| 位置 | ADR 原文 | 审计结论 | 处置 |
|---|---|---|---|
| §5.3 | 先抽查询再收敛写入 | 扁平状态上的查询会固化耦合 | **已裁决并回写**：改为容器 → 查询 → 写入；ADR §5.3 已同步修订 |
| §2.4 | 所有权靠字段归属 | 无强制手段 | 补"由测试与导入检查保证"（P0） |
| §2.6.6 | 提醒避免重复扣减 | 无结算协议 | 补同 tick 结算、拒绝事件、额度只在所有者侧（P3b；P3c 起所有者执行、契约只路由） |
| §2.4 | 契约层不持有状态、只路由 | P3b 曾把 contracts 登记为写入者 | **P3c 已修正**：结算移交领域所有者，红线测试强制 contracts 非写入者 |
| §2.2 | 动物复用通用执行能力 | 执行框架长在 agents 内；生命周期基础尚不存在 | 先抽通用能力，再做尺度分层（P5） |
| §2.2 | 植被有生物量/退化属性 | 运行时池无这些字段 | P4 前先扩池结构，或明确推迟 |
| 术语 | "环境模块" | 与 `modules/environment.py` 同名不同义 | **已裁决**：P0.5 先更名 |

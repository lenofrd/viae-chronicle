# 迁移对应与分步计划（migration-plan）

- **对应任务**：TASK-01 第 6 项
- **依据**：ADR 009（`c9f29a5`）+ 本目录另外四份审计
- **性质**：计划，不含代码改动。阶段一是只读审计。

## 1. 当前实现 → ADR 目标 对应关系

| 现行实现 | 实际职责 | ADR 目标归属 | 迁移动作 | 难点 |
|---|---|---|---|---|
| `ClimateModule` | 天气、季节、水位比例、灌溉档 | Environment（气候/水文） | 保留模块，水位归入水文子系统；增加水源节点库存以支撑取水 | 水文目前只有单标量，没有空间分布 |
| `EcologyModule` | 资源池初始化与再生 | Environment（植被/无机）+ Wildlife（鱼/猎物） | 池按 `resource_type` 拆分：植物类归环境，鱼与猎物归动物 | 运行时池无生物量/退化字段；`game_trail` 与 `hunt` 错配 |
| `AgentModule`（217KB） | 人口、家庭、劳作、经济、社交、并调度环境/土地/建造结算 | Human（多个子系统）+ 协调层 | 按动作类型与结算阶段拆分；采集/取水/野遇改走契约；环境结算移出 | 体量最大；`_settle` 内隐含跨域写；RNG 与事件顺序耦合 |
| `modules/environment.py` | 人文社区服务（维护、需求、储备、效率） | Human（社区/公共资源） | 更名（如 `community.py`），并入人文域；与 ADR 的 Environment 消歧 | 与 agents 双向调用，且被 22 项测试直接依赖 |
| `modules/land.py` | 地块初始化、转移、继承、用途 | Human（土地制度） | 保留为人类子系统；初始化数据来自 Environment 的公开结果 | 与 `terrain_cells` 存在两份肥力 |
| `modules/construction.py` | 建造配方、推进、修缮 | Human（建设） | 保留；去掉对 `agents.age_years` 的导入 | 生产路径无触发者 |
| `modules/governance.py` | 选举、议事、申诉 | Human（治理） | 保留；去掉对 agents 的依赖 | 生产路径无调用者 |
| `modules/tenancy_economy.py` | 租约、借贷、集市、公共仓储 | Human（经济） | 保留；把 `building.attributes` 里的库存提升为正式状态 | 库存藏在 attributes |
| `modules/social.py` | 认知、记忆、亲缘 | Human（社会关系） | 保留；把回放所需默认值改为事件可推导 | 回放反向依赖 |
| `core/replay.py` | 事件重建状态 | 内核（投影） | 去掉 `import modules.social` | 需要事件携带足够信息 |
| `worldgen/xigu.py` | 自然地理 + 聚落/人口 + 资源池 | 拆为 Environment 生成与 Human 聚落生成两段 | 先定义"自然环境公开结果"对象，再让聚落生成只读它 | 当前同一文件、同一函数链 |
| `SpatialNode.attributes` 中的资源字段 | 资源池的第二份副本 | 归各自所有者，attributes 只留静态属性 | 生成后不再复制资源池字段 | 观察层与测试可能依赖 attributes |

## 2. 推荐阶段顺序（与 ADR §5.3 有一处偏离，需确认）

ADR 写的是"先抽只读查询，再收敛写入"。本审计建议改为：**先拆状态容器，再建查询，最后收敛写入**。理由：在扁平 `WorldState` 上建的查询函数会为了取数而直接读所有领域字段，等于把耦合固化进新 API；容器先分，查询才有明确的读边界。

| 阶段 | 目标 | 主要改动 | 验收 |
|---|---|---|---|
| P0 基线加固 | 让边界可失败 | 新增架构测试：所有权 allowlist、导入边检查、配置一致性（`hunt` 目标池类型、两份肥力）、空资源池与未消费物资的告警测试 | `pytest -q -m "not long_run"` 全绿；新增测试在人为越界时能红 |
| P1 状态容器拆分 | 一域一容器 | `WorldState` 变为组合根：`environment` / `wildlife` / `human` 子容器；字段按表迁移；`building.attributes` 库存提升为状态；合并两份肥力（先选定唯一口径） | 全部现有测试不改断言仍绿；回放重建结果与拆分前逐字段一致 |
| P2 只读查询 | 读侧收口 | `EnvironmentQuery`、`SpatialQuery`、`WildlifeQuery`；替换 `getattr(world.state, ...)` 与散落字段读 | 人类模块不再 import 环境内部数据结构；查询有单元测试 |
| P3 写入契约 | 写侧收口 | `ResourceService`（采集/捕鱼/打猎/取水）、`EcologicalImpact`（洪涝/旱灾/滑坡/野遇）；所有者校验额度、同 tick 结算、拒绝事件、配对事件；调用方不得再直接改池/长势/健康 | 跨域写测试为 0；集市与采集守恒断言通过；新增事件有回放处理器 |
| P4 世界生成分段 | 自然先、聚落后 | 生成自然环境公开结果（地形、水系、气候带、土壤、植被、栖息地）；聚落生成只读；统一资源模型，取消 attributes 复制；`game_trail` 与猎物绑定 | 同种子生成结果逐字段等于现基线（除有意修正的错配）；`test_xigu_worldgen` 扩充 |
| P5 动物状态 | 真种群 | 动物独立状态模型与通用执行复用（先做聚合种群，后做个体）；食物网查询；性能预算与聚合阈值 | 新增动物生命周期测试；长程无 `agent_error`；性能不低于现基线 |
| P6 人文内部与调度 | 拆分大模块 | 把 `AgentModule` 的结算阶段拆为独立 Human 子系统；调度改为 ADR §2.7 六阶段；治理/建造接入生产路径或明确标记为未启用 | 六阶段顺序测试；治理/建造要么有生产触发者，要么测试标注为未启用 |

## 3. 必须先解决的决策（需要老板确认）

1. **P1 是否允许改变状态的数据形状**（子容器会改变 `WorldState` 的属性路径）。ADR 说不授权一次性重写，但容器拆分本身不可避免要动访问路径。
2. **两份肥力保留哪一份**：`field_fertility`（参与产量）还是 `terrain_cells.soil_fertility`（生成后闲置）。
3. **取水是否纳入 P3**：纳入意味着要新建水源库存，属新增机制而非重构；不纳入则水的守恒缺口保留到 P5。
4. **治理、建造、社区储备三个"测试专用"子系统**：接入生产路径，还是在计划里明确标注"暂不启用、仅保留测试"。
5. **迁移顺序是否接受 P1 先于查询**（对 ADR §5.3 的偏离）。

## 4. 每阶段的测试要求

- 不得删除现有实质断言；不得缩短长程测试来宣称完成（ADR §5.4）。
- 跨域写收敛必须由**会失败的测试**守护，而不是靠代码评审。
- 每个新契约（查询/命令）都需要：正常路径、拒绝路径、同 tick 幂等、回放重建、坏配置启动报错。
- 长程基线目前只有 1 项（2 年 720 tick），P1 与 P3 完成后应恢复一项 40 年 seeded 长程作为回归门禁；恢复前需老板批准时间预算。
- 性能基线：本次基线为 548 项 869 秒；P5 引入动物后必须重新记录，不得只报功能通过。

## 5. 回滚与提交策略

- 每阶段一个分支、一个 PR，阶段间不合并未完成的分支。
- P1 的容器拆分应可在单次提交内回滚，不与查询层改动混在同一 PR。
- P3 新增事件类型后，旧事件库回放测试（`pytest -k replay`）必须仍绿；不兼容时写显式迁移说明，不做静默降级。

## 6. 与 ADR 不一致处清单

| 位置 | ADR 原文 | 审计结论 | 建议 |
|---|---|---|---|
| §5.3 | 先抽查询再收敛写入 | 扁平状态上的查询会固化耦合 | 改为容器 → 查询 → 写入，并回写 ADR |
| §2.4 | 所有权靠字段归属 | 无强制手段 | 补"由测试与导入检查保证" |
| §2.6.6 | 提醒避免重复扣减 | 无结算协议 | 补同 tick 结算、拒绝事件、额度只在所有者侧 |
| §2.2 | 动物复用通用执行能力 | 执行框架长在 agents 内 | 先审计可抽取范围，给出抽取方案后再动工 |
| §2.2 | 植被有生物量/退化属性 | 运行时池无这些字段 | P4 前先扩池结构，或明确推迟 |
| 术语 | "环境模块" | 与 `modules/environment.py` 同名不同义 | ADR 或代码中先消歧 |

# 结果与后果

## 1. 目的
定义会话结束后，双方状态、关系、心理的修改，以及协议达成后的执行反馈。

## 2. 核心概念
- **结果分类**：达成（Agreement）、破裂（Breakdown）、悬置（Suspended）。
- **执行反馈**：达成后未必会立即执行（可能出现后续的反悔）。
- **信任修复**：破裂后的关系不会自然恢复，需要补偿或第三方斡旋。

## 3. 演化规则

### 3.1 达成协议
```
条件：stage = 达成
效果：执行 pending_effect（转移资源、签立契约）
      增加双方信任（如果过程顺利）或仅增加义务（如果过程艰难）
      生成 agreement_reached 事件
```

### 3.2 破裂与后果
```
条件：stage = 破裂
效果：心理状态下降，压力上升
      关系中的信任下降，恩怨增强
      如果涉及公开羞辱，触发舆论事件
      生成 negotiation_failed 事件
```

### 3.3 反悔与执行打折
```
条件：协议达成后，执行时发现条件变化（如歉收）
效果：违约方可能违约或减少交付
      触发生成 obligation_violated 事件
      债权人发起新的“讨债”会话。
```

### 3.4 悬置处理
```
条件：stage = 悬置
效果：暂不执行 pending_effect，保留会话上下文
      可能因外部环境变化（如灾荒）自行破裂或重启
      生成 session_suspended 事件
```

## 4. 与其他系统的接口
- 读：会话的最终 stage 与 proposal。
- 写：03-relationships 的信任与债务；02-psychological-state 的压力与恩怨；人物系统的资源与状态；04-information 的舆论触发。

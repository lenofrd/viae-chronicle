# 交互系统总览

## 1. 目的
定义人与人之间如何进行多轮交涉和拉扯。交互不是单轮判定（A 提要求 → B 同意/拒绝），而是包含试探、拒绝、加码、提条件、拖延、反悔的动态过程。系统要根据双方的信任、利益、情绪、信息、社会规范，实时生成每轮的回应。

## 2. 核心原则
- **多轮博弈**：一次交互是一个会话（Session），包含多个回合。
- **非理性与偏见**：人会受到情绪、关系历史、信息不对称、性别规范的影响，不会像机器一样做最优解。
- **主观重要性驱动**：事情越重要、风险越大，拉扯越久、越容易反复。
- **事件驱动**：每一轮交锋、每一次情绪波动、最终的结果，都必须生成事件。

## 3. 模块划分与依赖
```text
人物发起会话 (Request)
  ↓
门槛判定 (信任、利益冲突、情绪、信息、规范)
  ↓
回应选择 (同意/拒绝/拖延/提条件)
  ↓
拉扯循环 (直到达成、破裂或悬置)
  ↓
结果回馈 (关系变化、资源转移、心理影响)
```

- **01-session-structure.md**：会话的生命周期、参与方、话题。
- **02-negotiation-dynamics.md**：每轮回应的计算逻辑（门槛与选项池）。
- **03-importance-and-pacing.md**：主观重要性如何决定会话的轮数和节奏。
- **04-outcomes-and-consequences.md**：会话结束后的状态修改与后续影响。
- **09-dynamics.md**：长期的关系演化与信任修复。
- **10-state-and-records.md**：会话簇的记录规范。

## 4. 与其他系统的接口
- **读**：
  - 03-relationships：信任、利益权重、恩怨。
  - 02-psychological-state：压力、恐惧、情绪、性别角色冲突。
  - 02-institutions：制度底线（硬限制，不可谈判）。
  - 04-information：双方掌握的信息差。
- **写**：
  - 03-relationships：更新信任、债务、恩怨。
  - 人物系统：心理影响（压力、喜悦、记恨）、资源转移。
  - 记录系统：生成会话事件，供人生轨迹查询。

## 5. 事件类型总表
| 事件 | 产生模块 | 说明 |
|---|---|---|
| `session_started` | 01 | 会话开启，stage = 试探 |
| `session_importance_evaluated` | 03 | 评估双方主观重要性，决定最大轮数 |
| `session_round_completed` | 01 / 02 | 每轮回应结算，更新 proposal 与 stage |
| `prolonged_deadlock` | 03 | 高重要性且核心条件僵持，需第三方调解或跨 tick |
| `agreement_reached` | 04 | 达成协议，执行 pending_effect |
| `negotiation_failed` | 04 | 谈判破裂，关系恶化 |
| `obligation_violated` | 04 | 协议执行中违约或交付打折 |
| `session_suspended` | 04 | 会话悬置，保留上下文，可因环境变化重启或破裂 |
| `session_ended` | 01 | 会话关闭（达成 / 破裂 / 悬置） |
| `habituation_formed` | 09 | 同类话题反复达成，后续同类会话轮数减半 |

## 6. 第一版范围
- 第一版只做“一对一”的会话。
- 不接 LLM，回应从预定义的选项池中选择，由规则打分决定。
- 只支持明确的交涉（借粮、求爱、争论、换工），暂不做纯闲聊（闲聊走轻量级规则）。

## 7. 横切机制引用
- 变化速率（信任修复、习惯化）遵循全局 `09-dynamics/`：渐进、不可逆标记、带恢复条件。
- 会话簇记录遵循全局 `10-state-and-records/`：事件流为唯一真相，SessionCluster 为其投影。

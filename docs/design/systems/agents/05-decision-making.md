# 决策机制

## 1. 目的
定义人物每 tick 的决策流程，如何从需求评估走到最终行动。

## 2. 核心概念
- **感知 -> 评估 -> 意图 -> 行动**。
- **主观重要性**：决定在这个行动上花多少精力（低重要性快速决定，高重要性反复纠结）。

## 3. 演化规则

### 3.1 决策循环
```
条件：每 tick 轮到自己
效果：1. 感知当前环境和自身状态
      2. 更新需求权重
      3. 生成候选行动（根据所处空间、可用资源、性别规范限制）
      4. 效用打分（含 norm_penalty）
      5. 选择最高分行动
      6. 若得分相近且重要性高，进入纠结局
      7. 生成 action_executed 事件
```

> **004 裁决（2026-11-17，**M5 已落地**）——日内循环**：上述循环由「每 tick 一次」改为**日内逐动作贪心重规划**——每完成一个动作，重新感知、重新打分、选择下一个，直到当日工作窗 TU 耗尽或无可行动作（剩余 TU 自动转为恢复，见 01-physical-state.md §4.3）。复用同一效用打分器，不做全日规划、不引入序贯求解。「一日约 5 动作」为由时间 + 体力约束涌现的软目标，不硬编码。**M5 实测**：成人首年 2.60–2.71 动作/日（移动扣 TU 后通勤占去大半工作窗），低于 4–6 软目标下沿；动作构成以 fish / rest / eat / weave 为主，hunt 因往返超窗不可达。数值取舍见 06-actions.md §3.6 落地记录。

### 3.2 生存必要性门控（任务 11 修复，优先于效用竞争）
- **原则**：生存必要性优先于效用竞争。当「今天不进食，下一 tick 的饥饿值将跨过伤害阈值」且身上有任一可食食物时，直接选 `eat`，不再走打分排序。
- **触发条件**：`hunger + physiology.hunger_gain_per_tick >= physiology.hunger_health_damage_threshold`，且 `physiology.food_fields` 中至少一个字段 > 0。只读这两个配置字段，不引入新数值、不改效用公式与权重。
- **边界**：门控只在「有粮不吃」时拦截，不产生任何「凭空食物」；无粮可吃（所有 `food_fields` ≤ 0）时门控不触发，仍走原效用竞争（可能借粮/采集/歇息直至饿死），因此不会掩盖生计不可持续导致的死亡。
- 门控不写事件、不计数，避免刷屏；是否触发可从当天的 `agent_action_taken` 动作直接观察。

### 3.3 纠结局（主观重要性体现）
```
条件：最大得分与次大得分差距 < 阈值
效果：若重要性低，直接选最高分；
      若重要性高，消耗额外 tick 思考，或求助于人际关系。
      若面临“顺从规范”与“个人意愿”的冲突，纠结局时间加长。
```

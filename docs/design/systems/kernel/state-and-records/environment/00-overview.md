# 状态与记录子系统总览

## 1. 目的
统一定义自然环境的状态快照、事件流、查询接口，保证任何空间单元的当下状态可查、历史可追溯、人物一生可还原。本子系统不定义具体状态变量和事件类型，只定义记录格式和查询方式。

## 2. 核心概念
- 快照（snapshot）：每个空间单元在某一 tick 的完整状态，按子系统分组。
- 事件流（event stream）：按 tick 追加的不可变事件日志，是系统的唯一真相。
- 因果链（causal chain）：每个事件带 `cause_event_id`，指向触发它的父事件。
- 快照与事件的关系：快照是事件流在某一 tick 的投影，可以从事件流重放生成。
- 查询接口（query interface）：按人物、空间单元、资源、时间范围检索快照和事件。

## 3. 记录原则
- **事件流是唯一真相**：快照可以丢弃重建，事件流不可修改。
- **只追加**：事件只追加，不修改，不删除。修正通过新事件表达。
- **因果可追溯**：每个事件必须带 `cause_event_id`（外部注入除外，标记 `external: true`）。
- **空间可定位**：每个事件必须带 `location_id` 或 `unit_id`。
- **时间可排序**：每个事件带 `tick`，同 tick 内按 `sequence` 排序。
- **变化可还原**：每个状态变化事件带 `old_value`、`new_value`，可反向或正向重放。

## 4. 与其他系统的接口
- 01–09 各子系统声明自己的状态变量和事件类型，本子系统定义统一格式。
- 各子系统产生的事件写入事件流，按本子系统规范格式化。
- 查询接口被人物系统、记录系统、API 层调用。
- 本子系统不修改任何状态，只记录和查询。

## 5. 扩展预留
- 新事件类型：各子系统声明，本子系统格式不变。
- 新查询维度：在 query-interface.md 里扩展。
- 新存储后端：事件流和快照的存储实现可替换（SQLite → PostgreSQL → 专用事件存储），接口不变。
- 冷热分离：历史事件归档到冷存储，近期事件热存储，查询接口透明处理。

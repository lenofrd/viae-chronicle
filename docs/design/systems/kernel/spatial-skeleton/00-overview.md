# 空间骨架总览

> **能力状态**（E1 审计 2026-11-22）：**部分实现**——空间单元/连接/可达性已实现（`SpatialQuery` 契约）；风险梯度与时间成本表未落地。 逐项依据见[设计树对齐审计](../../../audits/ecology-foundation/design-tree-alignment.md)。

## 1. 目的
定义世界由哪些空间单元组成、单元之间怎么连接、人物怎么在单元之间移动。
所有自然环境子系统都挂载在空间单元上，按单元分别计算状态和演化。

## 2. 核心概念
- **空间单元（Spatial Unit）**：自然环境计算和记录的最小空间粒度。
- **单元类型**：镇域节点、田地片、河段、山层、资源点。
- **连接（Link）**：两个单元之间的通行关系，带时间成本、通行条件、风险。
- **可达性**：人物从当前位置到目标单元是否可行、要多久、有什么风险。
- **空间层级**：单元之间的包含关系（如山层包含资源点，镇域包含建筑节点）。

## 3. 空间单元类型总表
| 类型 | 说明 | 数量级（第一版） | 挂载的子系统 |
|---|---|---|---|
| 镇域节点 | 建筑/场所，如祠堂、磨坊、水井 | 5–10 | 气候、水文、地形、植被（周边） |
| 田地片 | 连片农田，按片管理 | 3–5 | 气候、水文、土壤与田地 |
| 河段 | 河流分段，如上游、镇前、下游 | 3 | 气候、水文、植被（湿地）、动物（鱼） |
| 山层 | 山脚、浅山、深山 | 3 | 气候、地形、植被、动物 |
| 资源点 | 具体采集/捕猎位置，挂在某层/某段下 | 6–8 | 植被、动物 |

## 4. 空间层级关系
- 镇域节点：平级，彼此通过镇内路径连接。
- 田地片：平级，各自连接镇域和河段/水渠。
- 河段：按上下游顺序连接，上游→镇前→下游。
- 山层：按深度嵌套，山脚→浅山→深山；资源点挂在具体山层下。
- 资源点：挂在山层或河段下，不独立于父单元存在。

## 5. 与其他系统的接口
- 所有自然环境子系统（02–08）**读**本子系统提供的空间单元清单和连接关系，按单元分别计算。
- 人物移动系统**读**本子系统的连接和可达性规则，生成移动事件。
- 记录系统**读**空间单元 ID，作为事件的位置字段。
- 本子系统**不读**其他子系统，只提供空间骨架。

## 5.1 事件类型

- `unit_state_changed`：{unit_id, subsystem, variable, old, new}
- `unit_disabled` / `unit_enabled`：{unit_id, cause}
- `movement_blocked`：{agent_id, from_unit, to_unit, reason}
- `movement_rerouted`：{agent_id, from_unit, original_target, new_target, cause}

本子系统不拥有演化状态，状态变量由 02–08 挂载在空间单元上。

## 6. 地点参数占位
具体地点（如 Brookvale）需要提供：
- 镇域节点清单：ID、名称、类型、描述、坐标感（地势高低、离河远近）
- 田地片清单：ID、名称、位置（近河/远河、上游/下游）、面积
- 河段清单：ID、名称、上下游顺序
- 山层与资源点清单：ID、名称、所属山层、资源类型
- 连接清单：from、to、通行时间、通行条件、风险

## 7. 扩展预留
- 新单元类型：在 `01-spatial-units.md` 里新增类型定义，现有子系统通过配置引用。
- 新地点：在 `locations/<地点>/natural-params.md` 里提供本地点单元清单，本子系统机制不变。
- 多镇/城市：城市作为新的单元类型或新的地点，连接关系扩展即可。

## 8. 横切机制引用

- 变化速率上限、滞后与累积、空间传播、可逆性规则见 `09-dynamics/`。
- 事件记录、快照结构、查询接口遵循 `10-state-and-records/`。
- 本子系统所有状态变化事件按 `10-state-and-records/event-stream.md` 的统一格式记录。

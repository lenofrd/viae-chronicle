# 建筑、生活环境与聚落设施系统

- **状态**：设计基线；当前实现覆盖疲劳生产、居住拥挤、基础公共服务容量、需求迟滞、修缮与天气工期，完整验收仍按本文阶段推进
- **适用机制**：跨地点通用
- **溪古镇配置**：沿用 `brookvale-town`，不得创建平行地点目录或世界 ID
- **关联决策**：ADR 001（事件与 Replay）、ADR 003（系统/地点分离）、ADR 005（土地权属、治理与自主建造）

## 1. 目标

把建筑、公共空间和自然环境从静态地图对象提升为影响居民日常生活的模拟要素，并让聚落能够根据长期、可解释的需求自主提出建设、维修、扩建或替代方案。

系统必须同时回答四个问题：

1. 居民身处何种环境，这种环境如何影响休息、劳动、健康和风险？
2. 建筑与公共设施能服务多少人，何时出现拥挤、等待或存储压力？
3. 聚落为什么需要新建筑，需求是否持续到值得投入资源？
4. 建筑如何在土地、材料、劳力、季节、治理和工期约束下建成并投入使用？

本系统不以“建筑数量越多越好”作为目标。已有设施的改善、修缮、扩容、共享、迁居、租用和等待，都应与新建竞争。

## 2. 领域边界

### 2.1 Building：建筑实体

建筑实体记录实际存在的物理设施：所属地块、空间节点、建筑类型、产权、占地、耐久、建成时间、启用状态和功能配置引用。

建筑不能直接把规则数值写进实体。功能、容量、维护和环境效应来自建筑类型定义；建筑实体只保存个体差异（如耐久、损坏、设施等级和局部改造）。

建筑必须落在合法 LandParcel 上，且通过 `LandParcel.spatial_node_id` 映射到唯一 Spatial Node。不得通过 attributes 中的备用 node_id 或家庭 home_node 推断施工地点。

### 2.2 BuildingType：建筑类型定义

建筑类型由机制层 schema 描述、地点配置提供具体参数。至少包含：

- `category`：dwelling / production / storage / public / shelter / infrastructure。
- `capacity`：居住、同时工作、同时服务或安全储存容量；不适用的容量为空或为零。
- `effects`：按用途声明的效果，不使用单一通用 buff。
- `maintenance`：周期维护需求、材料和成本。
- `construction`：占地、材料、基础劳动量、技能/工具要求及可建地用途。
- `risk_mitigation`：仅针对明确风险源的防护能力。

第一批建筑类型至少覆盖普通住宅、简易棚屋、作坊、仓房、水井/取水设施、集市或议事公共空间、野外临时庇护设施。既有静态地标可以逐步投影为建筑或公共设施，不得重复创建同一空间实体。

### 2.3 Environment：所在环境

环境效应由建筑功能、建筑状态、当前空间节点、天气、季节和活动共同决定。

环境分为：
- 有效建筑内部：住宅、作坊、仓房等。
- 有组织的公共空间：井、集市、道路节点、议事场所等。
- 一般户外：田地、河岸、林地和普通山地。
- 高风险自然区域：陡坡、深山、洪泛区及其他由地形/生态配置标记的区域。

“深山”或“野外”标签本身不能成为唯一风险依据。风险必须由地形、天气、活动、装备、同行者和设施防护等可解释因素构成。

## 3. 居民状态与日常环境效应

### 3.1 区分短期体力和长期疲劳

- `stamina` 表示短期可用体力，影响当日行动、移动和劳动；可通过短暂休息恢复。
- `fatigue` 表示跨日累积的长期疲劳，不能因一次 rest 或每日重置而清零；它反映连续劳作、睡眠不足和恶劣环境造成的负担。

每日结算建议采用有上下限的收支模型：

`fatigue_next = clamp(fatigue + labor_load + environment_load + sleep_debt - recovery, 0, 100)`

其中各项必须有可追溯来源，配置提供速率和上限。避免同一劳作既在行动执行时扣长期疲劳、又在日结时重复扣除。

### 3.2 休息与住宅

- 在可用住宅内完成主要睡眠时段，获得基础恢复。
- 床铺、取暖、遮蔽、干燥和合理居住容量可改善恢复。
- 拥挤、漏雨、寒冷、建筑破损和睡眠中断降低恢复。
- 在棚屋、临时庇护点或野外过夜，按实际遮蔽和天气提供较低或有条件的恢复。
- 住宅效果不能绕过饥饿、疾病、伤病等已有约束。

住宅容量超出后先形成拥挤压力，不立即施加最大惩罚；压力按持续时间平滑增长，并在入住人数回落或扩容后逐渐消退。

### 3.3 生产效率

- 作坊只提高与其设备/功能匹配的生产活动效率。
- 效率来源可以是工具、固定工位、遮蔽、照明和材料就近存放。
- 工作容量超出后产生拥挤、等待或效率递减，不允许无限叠加加成。
- 室内生产不应被错误地视为完全免疫疲劳、材料短缺或维护成本。
- 生产设施不能把居民锁定为某一职业；行动仍由居民需求、技能、库存、效用和时间共同决定。

### 3.4 公共空间与设施服务

公共设施必须表达服务对象、服务范围、服务容量和可用状态。

- 水井：取水服务能力、等待时间、可用性。
- 集市：交易/聚集容量，拥挤时降低交易效率或增加等待。
- 议事场所：集体活动容量；不应以拥挤直接剥夺居民权利。
- 道路/桥梁：通行能力和天气影响；通行权与土地权属仍分离。

公共空间的约束应优先体现为等待、排队、拥挤和行动机会成本，而不是无差别的数值惩罚。

### 3.5 野外风险

风险计算必须可解释、可配置、可测试。至少区分：
- 地形风险：坡度、湿滑、落石、涉水等。
- 环境风险：天气、能见度、洪水、寒冷等。
- 活动风险：采药、狩猎、采伐、负重和夜间活动等。
- 防护因素：道路、庇护设施、工具、经验、同行协助等。

每次伤害判定应记录风险来源、基础风险、修正项和最终概率。相同 seed、事件序列和配置必须可重放。保护地和深山禁区的建设限制优先于风险缓解需求，不得以修建设施绕开保护规则。

## 4. 容量、拥挤与服务压力

不同建筑使用不同容量维度，不能把所有容量压成一个数：

- `residents`：长期居住容量。
- `workers`：同时工作容量。
- `service_users`：单位时间服务容量。
- `storage`：预留的安全存储容量接口；当前家庭库存不启用容量上限，未来由地窖、储物棚、住宅储藏空间及扩建接入。

容量利用率应有舒适区、拥挤区和严重超载区。超过舒适容量时先产生压力；持续超载才逐渐影响睡眠、劳动、等待或损耗。恢复到合理容量后，压力应有缓慢消退过程，避免阈值附近反复震荡。

**当前存储规则**：家庭库存暂不设容量上限，不因库存超量自动损耗、出售、转存或划入公共储备。建筑 `storage` 容量字段作为后续接口保留；待地窖、仓房和扩建机制启用后，再按物资类型与建筑条件计算有效容量。家庭主动寄存共享仓储时，寄存余额仍归原家庭。

## 5. 建设需求：需求驱动而非脚本派单

### 5.1 需求来源

- 住房：长期居住拥挤、家庭分立、新家庭形成、现有住宅损坏。
- 生产：持续的工位瓶颈、工具/设备短缺、稳定的市场需求。
- 仓储：未来启用建筑储存容量接口后，才根据地窖/仓房容量与季节性收获峰值评估需求；当前无限家庭库存不产生仓储扩建压力。
- 公共服务：水井/道路/集市服务能力长期不足，排队和绕行成本持续偏高。
- 安全：可重复发生的风险暴露，且有合法、有效的缓解设施。
- 维护：建筑耐久下降，维修比重建更经济时优先维修。

需求必须来自观测到的状态、事件和预测窗口，不得按固定年表无条件生成建设任务。

### 5.2 缓冲与迟滞

单次超载、出生或丰收不应立刻触发强制建设。需求评估需使用：
- 容量安全余量；
- 连续超载天数/季节；
- 人口和产量的趋势，而非单日峰值；
- 空置住宅、可租用空间和现有设施的替代能力；
- 可用土地、材料、劳动力、资金和维护能力；
- 需求等待时间与最晚合理处理时间。

需求状态建议为 `latent → emerging → persistent → prioritized → proposed → approved → under_construction → fulfilled`，并允许 `deferred`、`resolved_by_alternative`、`expired`。需求未达到持续阈值时只记录压力，不产生强制处罚。

### 5.3 冗余与韧性

聚落不应追求 100% 利用率。对住宅、仓储、供水和公共服务分别配置目标余量，并考虑季节峰值、人口变化、灾害和设施维修。

冗余收益包括应对分家、临时安置、歉收/丰收、设施故障和集体活动；冗余成本包括维护、材料占用、闲置折旧和劳力机会成本。建设评价应比较新增能力带来的边际收益与全生命周期成本。

## 6. 建造、工期与生命周期

建造流程与 ADR 005 的土地权属、审批和事件规则一致：

1. 需求识别与方案比较；
2. 地块/空间/用途/通行/灾害风险校验；
3. 个人家庭审批或集体议事；
4. 材料和资金筹备；
5. 劳动力排期；
6. 施工；
7. 验收与投入使用；
8. 日常维护、修缮、扩建、改建、废弃或拆除。

工期以总劳动量和每日有效投入推导，不使用“一次施工即竣工”的抽象捷径。每日投入受可用成年劳力、体力、长期疲劳、技能、工具、天气、季节、农忙和材料供应影响。一个劳动单位必须有明确的时间口径；不得把多人劳动或多次调用重复计入同一 Tick。

施工期间项目保留占地和已投入材料。暂停不自动返还已消耗资源；取消、废弃和恢复必须记录事件并明确材料残值、占地释放和安全处置。建成建筑从验收/竣工事件后才开始提供完整功能，施工中的棚架或临时设施若提供有限效果，必须单独配置。

维修应优先于拆建：当修缮能以更低成本恢复足够功能时，不应重复建造替代建筑。

## 7. 建设价值评估

候选方案比较应考虑：

`net_value = service_benefit + risk_reduction + resilience_value - construction_cost - maintenance_cost - opportunity_cost`

其中收益应按合理预测期折算，且受真实需求约束。没有需求、没有合法地块或维护能力不足时，不应仅因资源充足就持续建造。

可比较的替代方案包括：修缮、扩建、增设设备、共享、租用、迁居、调整设施用途、改善道路和等待。公共建设还必须考虑利益分布、受影响家庭和现有治理程序。

## 8. 事件与 Replay

建筑和环境系统的关键变化必须事件溯源。至少覆盖：
- 建筑创建、启用、损坏、维修、扩建、停用和拆除；
- 容量压力形成、变化和解除（避免每 Tick 重复刷相同事件）；
- 居民每日疲劳结算及主要来源；
- 设施服务/等待/拥挤的可解释结果；
- 伤害事件的风险来源和概率修正；
- 建设需求形成、升级、延期、替代解决和完成；
- 施工劳动、材料消耗、暂停、恢复、取消、竣工。

派生值应尽可能由状态和事件计算，避免同一事实存在多份互相漂移的真相源。Replay 后必须恢复建筑、项目、需求、耐久、疲劳及相关事件投影。

## 9. 配置与地点分离

通用 schema 与算法位于系统模块；建筑类型参数、地形风险、初始建筑、容量目标、缓冲期和冗余目标位于地点配置。

溪古镇继续使用现有 `brookvale-town` 地点与既有空间节点。不得新增 `xigu-town` 目录、世界 ID 或重复地标。原有节点可逐步绑定建筑/公共设施，但不能重复计算同一处设施。

任何配置缺省都应有兼容策略，不能使旧地点或既有测试因缺少新字段而无法加载。

## 10. 分阶段实施与验收

### 阶段一：建筑功能与生活环境

- 建立建筑类型定义和建筑实体到地块/空间节点的严格映射。
- 接入日结疲劳收支；住宅睡眠条件影响恢复。
- 生产设施只对匹配活动提供有限效率修正。
- 公共设施记录基础服务容量；自然环境风险由地形/天气/活动来源构成。
- 事件可 Replay；默认配置保持旧地点可运行。
- 测试住宅恢复优于无庇护野外、疲劳跨日累积、作坊效果只影响匹配生产、风险修正可解释且确定性、建筑节点映射一致。

### 阶段二：容量与拥挤

- 加入居住、工作、服务和存储容量。
- 引入渐进压力、宽限期和恢复迟滞。
- 排队、等待、拥挤和超量储存影响对应行为，不施加无关惩罚。

### 阶段三：建设需求与冗余

- 从长期压力生成需求，并允许替代方案解决。
- 按地点配置安全余量、持续阈值、优先级和等待宽限期。
- 建设价值考虑维护成本、机会成本和公共利益。

### 阶段四：现实工期与长期校准

- 将农忙、季节、天气、疲劳、技能、工具、劳力和材料供应纳入施工进度。
- 支持维修、扩建、改建、废弃和拆除。
- 进行至少 360 天及多年度模拟，检查住房压力、设施利用率、疲劳分布、受伤率、建设频率、闲置维护成本和家庭生计是否出现失控。

## 11. 明确不做的事

- 不因单日超载立即惩罚或强制开工。
- 不把所有建筑效果合并为一个通用 buff。
- 不把自然风险简化为节点名称判定。
- 不凭空生成土地、材料、工人或公共资金。
- 不允许建造行为绕过土地权属、保护地、通行权和治理审批。
- 不让建筑加成取代居民自主选择和生计多样性。
- 不在第一阶段同时引入复杂人口预测、市场均衡和全套公共财政；先建立可解释、可测试的基础闭环。

## 12. 当前实现边界（2026-11-18）

以下内容已进入 PR #12 的溪古镇实现线，均沿用 Brookvale Town 的空间节点和配置目录：

- 长期疲劳由劳动/通勤事件结算；疲劳不仅影响行动效用，也按同一效率因子实际影响耕作长势、收获、采集和织布产出。
- 住宅提供疲劳恢复；入住率超过舒适容量后，恢复量按拥挤程度下降。住宅损坏会降低恢复，失去可用住宅则按户外恢复。
- 作坊加成严格按 LandParcel.spatial_node_id 作用于匹配的织布活动，不跨节点、不跨行动类型。
- 野外伤害按地点配置的风险乘数修正；浅山、深山、河段分别配置暴露值，恶劣天气和长期疲劳会进一步提高采集受伤风险。
- 水井按每日取水吞吐量限制；集市按同时到场容量限制，超额家庭本日无法入场，访问顺序按日期轮转，避免固定户籍顺序长期垄断。
- 住房需求、户内拥挤、持续织布工位需求和建筑维修形成缓冲需求信号。当前家庭库存不设容量上限，不产生家庭储存压力或仓储扩建需求。需求经历 latent / emerging / persistent / prioritized，不会自动创建建筑或在首次超载时处罚；事件可 Replay。
- 新建和扩建按 ADR 005 的土地权利与建设审批分级办理：家庭日常修缮自主并登记，低影响附属设施由家庭自主建设、里正备案，普通住宅/小型作坊/常规生产棚由里正日常审批，涉及集体土地、越出宅基地边界或造成重大公共影响的项目提交议事会；公共设施和集体资金建设由议事会决定。拆除须遵守土地权利、安全与公共通行约束并记录事件。建设项目按多日劳动项目执行；疲劳、恶劣天气和农忙季节会降低施工进度，扩建占用地块剩余面积，拆除释放建筑占地，相关事件可 Replay。
- 建筑耐久按日缓慢损耗；耐久下降会形成维修需求。家庭库存当前不设容量上限，也不发生超限损耗；建筑储存容量接口保留，待地窖/仓房和扩建机制落地后启用。

仍需补齐后才算完整验收：

- 把服务容量从“准入上限”扩展为可观察的排队/等待时间，并覆盖议事空间和道路通行能力。
- 设计并实现地窖/仓房储存容量及扩建接口；当前家庭库存无限，不启用超限损耗、自动转存或自动出售。共享仓储的家庭寄存余额与公共储备严格分离。
- 增加周期维护资金/劳力安排和改建（改变用途/功能）的完整生命周期；目前已有自然耐久损耗、修缮、扩建和拆除。

## 冬季避寒

有效住宅除提供睡眠恢复外，也能降低冬季寒冷伤害。减免比例由 `environment.dwelling_cold_protection` 配置，并按住宅耐久度折算；无住宅或住宅损毁时不提供保护。衣物达到保暖门槛仍可完全避免寒冷伤害。这样住宅和衣物分别承担避风与个人保暖，不会把无衣物的初始家庭直接判为必死。

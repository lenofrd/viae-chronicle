# 自然环境总览

## 1. 目的

自然环境子系统负责定义 Brookvale 小镇所在世界的**自然侧**：气候、水文、地形、土壤与田地、植被、动物、灾害。它回答三个问题：

- 世界现在是什么样？（当下快照）
- 世界怎么变成现在这样？（演化历史）
- 世界接下来会怎么变？（演化规则）

自然环境按自己的节律演化，不等人感知。人物只能感知、响应、有限改变，不能凭空设定。

## 2. 设计原则

**2.1 自然先于人文**
自然环境先于人物行动存在并演化。人物行动可以改变环境，但改变是有限、有延迟、有代价的。禁止“人物想下雨就下雨”。

**2.2 五条现实性**
所有自然变量受五条约束：

- **因果链**：每个环境变化都要有前因事件，不能凭空发生（外部注入要标注为外部事件）。
- **时间尺度**：季节不跳变；旱情积累若干天才成灾；山洪需要前期降雨累积加短时暴雨触发；地力恢复以年计。
- **空间差异**：同一事件，上游/下游、阳坡/阴坡、近山/深山影响不同，禁止全局一刀切。
- **滞后与累积**：今天砍树，山林不会明天退化；连续砍一个月才明显变少。环境状态带趋势和累积量，不是瞬时值。
- **可逆/不可逆**：区分可逆变化（地力、山林、河道淤积）和不可逆变化（古树被砍、山洪冲毁的田、滑坡改变的地形），不可逆的标记，可逆的带恢复条件和时间。

**2.3 历史与快照并存**
每条自然要素同时存两样东西：

- **演化历史（事件流）**：回答“为什么现在是这个样子”。
- **当下快照（空间状态）**：回答“此刻这里是什么样”。

两条线缺一不可。只有历史没有快照，人物行动没有落脚点；只有快照没有历史，记录失去因果。

**2.4 空间有差异**
自然环境按空间单元分别计算，不做全局平均。上游截水对下游影响大于对上游；同一场雨，山区和河边影响不同；草药分布不均匀，各在各的位置。

**2.5 精度可简化，逻辑不可简化**
不需要模拟每滴水的流向、每种草的完整生长周期。简化的是数值精度和微观物理过程，不是因果逻辑、时间尺度、空间差异。

## 3. 空间骨架

自然环境分四层，从外到内：

**3.1 大山（背景层）**
- 山脚、浅山、深山三层，代表可达性和风险梯度。
- 山“很大”体现为进山耗时久、容易迷路、天气多变、有野兽和滑坡，不是地图格子多。
- 深山第一版不开放精细移动，只作为高风险资源点和事件源（野兽下山、山洪源头、雾瘴）。

**3.2 河流（生命线层）**
- 按河段划分：上游段、镇前段、下游段。
- 每段有水位、流速、浑浊度、可渡性、取水点。
- 河宽体现为绕行远、渡河有风险、汛期不可过。
- 上游和下游是天然的利益对立结构。

**3.3 田地（生产层）**
- 按片管理，每片有位置（近河/远河、上游/下游）、面积、地力、水源条件、当前作物、长势。
- 远田和近田的劳作成本不同；靠河田和靠坡田的缺水风险不同。

**3.4 镇域（居住层）**
- 镇内建筑节点（祠堂、磨坊、水井、药铺等）本身属于人文环境，但其自然侧写要记录：地势高低、离河远近、是否易涝、周边植被、水井水位、磨坊水轮动力、街面积水、柴薪堆放。
- 镇域是人与自然交界的日常场所。

## 4. 子系统依赖图

自然环境各子系统之间的读写关系：

```text
气候 (02)
  ├─ 驱动 → 水文 (03)：降水影响水位、流速
  ├─ 驱动 → 土壤与田地 (05)：降水、温度影响土壤湿度和作物
  ├─ 驱动 → 地形 (04)：暴雨影响滑坡风险
  └─ 驱动 → 灾害 (08)：旱涝累积触发灾害

水文 (03)
  ├─ 驱动 → 土壤与田地 (05)：水位影响灌溉条件
  ├─ 驱动 → 植被 (06)：河边湿地资源受水位影响
  └─ 驱动 → 灾害 (08)：水位超阈值触发山洪

地形 (04)
  ├─ 驱动 → 植被 (06)：坡向影响资源分布
  └─ 驱动 → 灾害 (08)：滑坡风险点触发滑坡

土壤与田地 (05)
  └─ 驱动 → 植被 (06)：地力影响田边植被

植被 (06)
  ├─ 驱动 → 动物 (07)：植被退化影响猎物和野兽行为
  └─ 驱动 → 土壤与田地 (05)：植被覆盖影响水土保持

动物 (07)
  └─ 驱动 → 灾害 (08)：野兽下山事件

灾害 (08)
  └─ 反馈 → 所有子系统：改变状态并成为后续事件的父事件

演化机制 (09) 和 状态与记录 (10) 是横切层，被所有子系统引用。
```

**依赖原则**：上游子系统只提供状态和事件，不直接修改下游子系统；下游子系统读取上游状态，按自己的规则演化。

## 5. 演化机制（四种驱动源）

**5.1 tick 驱动（慢变量）**
季节推进、地力变化、河道淤积、山林再生、资源恢复。按日/季推进，不依赖事件。所有慢变量有变化速率上限，禁止瞬移。

**5.2 事件驱动（快变量）**
暴雨、山洪、旱、虫害、滑坡、火灾、野兽下山。有触发条件和因果前因，触发条件依赖前期累积状态。

**5.3 累积效应（涌现）**
多人采集/砍伐/捕猎导致资源退化；修渠、造林、轮耕改变环境。不是谁“决定”的，是聚合出来的。

**5.4 外部注入**
从接口写入的自然事件，标注为外部事件，同样进入事件流，同样受五条现实性约束。

详细机制见 `09-dynamics/`。

## 6. 状态与记录的通用约定

**6.1 空间单元**
每个空间单元（镇域节点、田地片、河段、山层、资源点）有唯一 ID 和类型。状态变量按子系统声明，挂在空间单元上。

**6.2 快照**
每个 tick 可查每个空间单元的当前状态。快照包含：本子系统所有状态变量的当前值 + 趋势标记（变好/变差/稳定）+ 累积量。

**6.3 事件流**
每个自然变化是一个事件，带统一 payload：

```text
tick, location_id, variable, old_value, new_value,
cause_event_id, effect_scope, reversible, recovery_time
```

环境事件和人物事件共享同一因果链。山洪是事件，它同时改变河段水位、田地状态，并成为后续人物“修渠”“迁徙”“心理变化”的父事件。

**6.4 查询组合**
- 查某人一生：事件流每条带当时环境快照摘要。
- 查某个空间：返回演化历史 + 当前快照。
- 查某个资源：返回存量变化、采集压力、退化/恢复事件。

详细字段规范见 `10-state-and-records/`。

## 7. 第一版范围

**做**：
- Brookvale 镇域 5–10 个建筑节点（自然侧写），田地 3–5 片，河流 3 段（上游/镇前/下游），山 3 层加 6–8 个具体资源点。
- 季节、降水、水位、地力、作物、柴薪、常见草药、鱼、野兽下山、山洪、旱、虫害、滑坡。
- 慢变量按日/季推进，快变量按事件触发，累积效应做“采集压力 → 资源退化”一条。
- 快照 + 事件流双记录，人物行动带环境快照。

**不做（预留接口）**：
- 完整气候模型、完整食物链、深山精细移动、多区域传播、全球天气。
- 这些作为配置和事件类型的扩展位，第一版不实现。

## 8. 扩展预留

- **多地点**：`systems/` 只写通用机制，具体地点的参数和特殊设计放 `locations/<地点>/`。加城市时新建 location，通用机制不动。
- **新子系统**：作为新文件夹加入 `systems/natural-environment/`，在依赖图里声明读写关系。
- **新驱动源**：在 `09-dynamics/drivers/` 里新增驱动类型，现有子系统通过配置引用。
- **新事件类型**：各子系统在自己的文档里声明，`10-state-and-records/` 的通用 payload 结构不变。
- **LLM 接入**：作为旁路进程读事件流、写叙事文本，不改变自然环境的状态模型和演化规则。

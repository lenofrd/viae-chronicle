## 第二层：子系统内部一致性（逐个看，每个 10 分钟）

对每个子系统 `00-overview.md`，检查三件事：

**检查 2.1：状态变量是否被子文件覆盖**

`00-overview.md` 第 3 段列了状态变量表。打开该子系统的每个子文件，看这些变量是否都有人认领。比如 `02-climate/00-overview.md` 列了 `temperature`、`precipitation`、`humidity`、`wind`，这些应该在 `weather.md` 里被定义；`drought_accumulation`、`flood_accumulation` 应该在 `drought-flood.md` 里。如果某个变量在 `00` 里出现，但所有子文件都没定义它，就是遗漏。

**检查 2.2：事件类型是否被子文件覆盖**

`00-overview.md` 第 5 段列了事件类型清单。打开子文件，看每个事件类型是否在某个子文件里出现了定义和 payload。比如 `02-climate/00-overview.md` 列了 `season_changed`，它应该在 `seasons.md` 第 5 段出现；`drought_triggered` 应该在 `drought-flood.md` 出现。

**检查 2.3：地点参数占位是否完整**

`00-overview.md` 第 7 段列的地点参数，应该在子文件第 7 段（或最后一节）里能找到具体条目。如果 `00` 说“需要季节长度”，`seasons.md` 的“地点参数占位”里必须有一行 `每季长度（tick）`。

**用一个简单命令辅助：**

```bash
# 看每个子系统的 00 里声明了多少状态变量和事件类型
grep -c "|" 02-climate/00-overview.md

# 看子文件里有没有对应的关键词
grep -l "season_changed" 02-climate/*.md
grep -l "drought_accumulation" 02-climate/*.md
```

## 第三层：跨子系统接口一致性（重点，最容易出问题）

每个子系统 `00-overview.md` 第 6 段写了“读谁、写谁”。这是双向承诺，必须两边对得上。

**检查方法：建一张接口对照表。**

打开每个子系统的第 6 段，把所有“写”的声明抽出来，看接收方有没有对应的“读”声明。比如：

- `02-climate` 写：“向 03-hydrology 提供降水、温度、季节系数”
- 打开 `03-hydrology/00-overview.md` 第 6 段，应该能看到“读：02-climate 的降水、温度、季节系数”

如果 `02` 说写给 `03`，但 `03` 没说读 `02`，就是接口断裂。反过来，`03` 说读 `02` 的某个东西，`02` 没提供，也是断裂。

**按这个清单逐个核对：**

```
02-climate   写 → 03-hydrology     03 是否声明读 02 的降水/温度/季节
02-climate   写 → 05-soil-fields   05 是否声明读 02 的降水/温度/季节
02-climate   写 → 04-terrain       04 是否声明读 02 的暴雨
02-climate   写 → 08-hazards       08 是否声明读 02 的旱涝累积/极端天气
03-hydrology 写 → 05-soil-fields   05 是否声明读 03 的灌溉条件/水位
03-hydrology 写 → 06-vegetation    06 是否声明读 03 的水位
03-hydrology 写 → 07-fauna         07 是否声明读 03 的水位/流速/浑浊度
03-hydrology 写 → 08-hazards       08 是否声明读 03 的山洪风险/淤积
04-terrain   写 → 06-vegetation    06 是否声明读 04 的坡向/坡度
04-terrain   写 → 08-hazards       08 是否声明读 04 的滑坡风险
05-soil      写 → 06-vegetation    06 是否声明读 05 的地力/湿度
05-soil      写 → 08-hazards       08 是否声明读 05 的虫害风险
06-vegetation 写 → 04-terrain      04 是否声明读 06 的植被覆盖
06-vegetation 写 → 05-soil-fields  05 是否声明读 06 的植被覆盖
06-vegetation 写 → 07-fauna        07 是否声明读 06 的植被类型/覆盖
06-vegetation 写 → 08-hazards      08 是否声明读 06 的植被干燥度/退化
07-fauna     写 → 08-hazards       08 是否声明读 07 的食物短缺/攻击性/下山
08-hazards   写 → 03/04/05/06/07   各子系统是否声明读 08 的灾害后果
```

这条最容易漏。比如 `08-hazards` 说“写：03-hydrology 改变水位”，但 `03-hydrology` 的“读”里没写“08-hazards 的洪水改变水位”，就是断裂。

## 第四层：09/10 横切机制是否被引用

**检查 09 被引用：**

打开 01–08 各子系统的演化规则段，看有没有提到“受变化速率上限约束”“有 1–3 tick 滞后”“沿路径传播”“可逆/不可逆”。如果某个子系统完全没提 09 的机制，检查它的规则是不是漏了约束。

**检查 10 被引用：**

打开 01–08 各子系统的 `00-overview.md`，看第 6 段或文档末尾有没有提到“事件按 10-state-and-records 的规范记录”“快照按 10 的结构生成”。如果完全没提，补一句引用。

## 建议的检查顺序

1. **先跑第一层命令**，把文件补齐。文件不齐，后面查不了。
2. **从 02 开始逐个查第二层**，因为 02 是上游，02 的状态变量和事件类型最基础。
3. **查完 02–08 后做第三层接口对照**，这时候你对各子系统已经熟了，对照表能快速发现断裂。
4. **最后查第四层**，09/10 是横切，放在最后统一看引用情况。
5. **问题记进 CHECKLIST.md**，改完划掉。

一句话：**先数文件，再查每个子系统内部“00 说的和子文件做的是否一致”，再查子系统之间“说的写和说的读是否对得上”，最后查 09/10 有没有被引用。** 第三层最容易出问题，也最重要。

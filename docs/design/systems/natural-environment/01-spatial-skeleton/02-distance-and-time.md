# 距离与时间成本

## 1. 目的
不用连续坐标，用**步行时间**表达空间距离，让人物的移动有现实成本。

## 2. 核心概念
- **通行时间（travel_time）**：从单元 A 到单元 B 所需 tick 数（1 tick = 1 天时，用“时辰/半天/一天”表达）。
- **体力消耗（stamina_cost）**：移动消耗的体力，影响当天还能做多少事。
- **通行条件（condition）**：天气、季节、水位、路况对通行的影响。
- **风险（risk）**：移动途中可能遭遇的事件（迷路、野兽、滑坡、渡河危险）。

## 3. 连接定义
每条连接（link）包含：
| 字段 | 说明 |
|---|---|
| from / to | 单元 ID |
| base_time | 基础通行时间（无干扰时） |
| base_stamina | 基础体力消耗 |
| condition_modifiers | 条件修正：雨天×、汛期×、夜间×等 |
| risk_events | 途中可能触发的事件池 |
| bidirectional | 是否双向（默认是） |

## 4. 时间尺度约定
- 镇内节点之间：几分钟到一刻钟（不到 1 tick，但记录时算作“短途移动”，不单独占 tick）。
- 镇域到田地/河边/山脚：半小时到两小时（占 1 tick 的一部分）。
- 山脚到浅山：半天往返（占大半天）。
- 浅山到深山：一天以上（需要跨 tick，第一版深山不开放精细移动，只作为事件源）。
- 渡河：取决于河段宽度和水位，平时可涉水/渡船，汛期不可渡。

## 5. 移动规则
- 人物决定移动 → 检查可达性（见 03-accessibility）→ 计算通行时间 → 生成移动事件 → 到达后更新位置。
- 短途移动（镇内）不单独占 tick，但记录为事件。
- 长途移动（去浅山、跨河）占 tick，途中可能触发风险事件。
- 移动事件 payload：`{agent_id, from_unit, to_unit, start_tick, end_tick, cause, encounters}`

## 6. 与其他系统的接口
- 读：气候（天气修正通行）、水文（水位影响渡河）、地形（山路风险）。
- 写：人物位置状态、移动事件。
- 风险事件由 08-hazards 和 07-fauna 提供事件池，本子系统只负责触发时机。

## 7. 地点参数占位
- 每条连接的 base_time、base_stamina、condition_modifiers、risk_events。
- 各地点的尺度约定（镇内多大、田多远、山多深）。

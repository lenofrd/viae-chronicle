# 可达性

## 1. 目的
定义人物能否从当前位置到达目标单元，以及需要满足什么条件。

## 2. 可达性判定
一次移动请求要依次通过：
1. **连接存在**：from 和 to 之间有直接连接，或可通过多跳路径到达。
2. **通行条件满足**：天气、季节、水位、路况不构成阻断。
3. **人物能力满足**：体力足够、没有伤病限制、没有社会限制（如禁地）。
4. **时间可行**：当前 tick 剩余时间够走完，或允许跨 tick。

任一条不满足，移动失败，生成 `movement_blocked` 事件，记录原因。

## 3. 阻断类型
- **硬阻断**：连接不存在、渡口关闭、山路中断、禁地。无法通行。
- **软阻断**：条件变差导致时间/体力成本上升，但仍可通行。人物可自行决定是否走。
- **风险阻断**：通行可行但风险过高，人物按心理和重要性判断是否冒险。

## 4. 移动失败与替代
- 移动失败后，人物可选择：等待条件改善、绕行、放弃目标、改去别处。
- 这些选择本身是决策事件，带因果。

## 5. 与其他系统的接口
- 读：02-distance-and-time 的连接定义、03-hydrology 的水位、02-climate 的天气、04-terrain 的滑坡状态。
- 写：`movement_blocked`、`movement_rerouted` 事件。
- 与人物系统接口：可达性判定结果作为人物决策的输入之一。

## 6. 地点参数占位
- 各地点的禁地清单、渡口清单、山路清单。
- 各阻断类型的触发条件（如“水位 > X 时渡口关闭”）。
